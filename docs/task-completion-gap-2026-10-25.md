# Minion 任务结束机制：本轮修复与剩余差距

## 可复现的提前结束入口

1. 原结束核验器的 `kind=answer` 由同一个模型返回。即使当前用户目标是“生成/修改/开发”，模型也可返回 `completed + answer + reply`，绕过“实际操作需要成功工具收据”的检查。`StopGateTest.operationalGoalCannotBeDowngradedToReplyOnlyAnswer` 回放此入口。
2. 即使有成功工具收据，旧检查只看“有成功”，不能区分读取/状态查询和写入/构建；`Read` 成功不能证明新报告已生成。现在对明显操作目标和产物目标分别要求可核对的操作、写入/构建收据。
3. 候选回复若还明确承诺 Agent 下一步操作，旧完成判定可被模型意见或完成标记放行；现对高置信操作任务拦截此类阶段答复，完成标记没有优先权。
4. 核验器可返回 `waiting_user`，但回复并未指出要用户提供什么。现在无具体材料/权限/选择缺项且无未决工具副作用时，改为有界继续；真正缺资料/权限、用户主动中断或结果不明的写入仍应暂停。
5. `Write/Edit` 成功只证明当时执行过，不证明结束时文件仍存在且未变化。现在对当前任务可追踪的输出文件重新核对状态和 SHA-256；缺失、变更或权限不可核验时不批准完成。
6. 轮数上限、无进展预算、模型空响应、异常或结束核验未确认后的暂停原因写入 `TaskState.pauseReason`，随会话保存，在 `/task` 查看；`completed` 不再保留暂停原因。任务仍不会无限自续接。

## 与 Codex 的差距（公开资料边界）

OpenAI 官方 [Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) 描述的是**可选的、线程级 Goal**：用户定义结果、验证面、约束、迭代策略和阻塞条件；空闲后在预算内按证据继续，预算耗尽不等于完成。普通一次性问答不必启用 Goal。Minion 当前 `TaskState` 虽持久化目标和结束决策，但每轮依赖用户文字与启发式最低证据，尚无同等级的用户可审查完成契约及空闲后安全续接调度。

| 方面 | 本轮 Minion 状态 | 仍缺什么 |
|---|---|---|
| 完成标准 | 高置信操作目标的证据门槛 + 可选用户登记的程序验收规则 | 对复杂任务由用户确认“交付物/验收命令/允许边界”；文字启发式不能替代业务验收 |
| 证据 | 工具收据、当前任务ID、待办/子任务、断点和 `Write/Edit` 文件哈希 | Bash、Excel、Browser、数据库及 EXE/APP 成品尚无统一产物登记与专用验证器；收据成功不等于结果正确 |
| 继续/暂停 | 单轮内有界续接；假 `waiting_user` 不直接停；暂停原因持久化 | 轮数上限后仍需人工点“继续”，没有 Goal 式空闲事件调度、预算与用户控制的完整生命周期 |
| 模型判断 | 独立短请求，但仍由当前 Qwen 模型评估；确定性门禁在模型意见之外 | 同一模型可能语义错判；需要真实内网 Qwen 场景回放、故障注入和人工抽样，不能声称永不误停 |
| 大任务 | 压缩/事件日志保留任务和原文；当前结束快照有界引用收据、文件 | 长任务早期证据可能不在最近 24 条收据、64 个输出文件检查范围内；需按任务里程碑建立可追溯的验收清单 |

官方 [Codex 长任务实践](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) 强调明确的 `done when`、阶段验证与失败后修复。Minion 下一期应先把用户认可的完成契约做成会话级控制面，再给 Excel/网页/代码/数据库等交付物补专用验证器，而不是只增加“继续”提示词。

## 验收边界

本轮是源码修改，不生成内网更新包。Java 8 离线定向回归 **321 项通过、0 失败**，覆盖纯问答、回复冒充完成、只读证据冒充写入、完成标记加下一步承诺、假等待用户、真实缺资料、文件变化、子 Agent、任务队列及暂停原因保存。原有若干“模型说生成完成但未执行工具”的测试改成了有实际工具动作的回放；新会话标题回调原先可能在标题生成前被会话排序事件提前触发，也一并修正。受当前沙箱 localhost 限制，未把 HTTP/MCP 全量用例计入这 321 项。实际 Win7/Qwen 27B 上仍需用曾经“莫名其妙结束”的真实会话和工具记录回放，核对是否误停/误继续/误完成，以及额外审核耗时和 token。没有用户提供的真实失败记录前，不能把本地模拟当作问题已完全根治。
