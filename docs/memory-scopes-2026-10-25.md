# Minion 核心摘要、跨对话与跨项目记忆（源码阶段）

状态：仅本地源码；未制作 Win7 更新包，也未在内网模型/真实长期会话上验收。

## 参考产品的真实边界

- [OpenAI 官方 Codex Memories](https://learn.chatgpt.com/docs/customization/memories)：**本地 Codex 记忆确实可以跨会话/项目复用有用上下文**，与 ChatGPT 网页记忆分开，默认关闭。启用后，从符合条件的旧会话异步提取，跳过活跃/过短会话、生成字段脱敏；存于 `~/.codex/memories/`，有摘要、稳定条目、近期输入及证据。使用与生成分别由 `memories.use_memories`、`memories.generate_memories` 控制，会话还有 `/memories` 开关；不能据此断言它必然记住每句话或精确内部算法。[个人化说明](https://learn.chatgpt.com/docs/personalize)称 Codex 跨会话个人指令放在全局 `AGENTS.md`，项目还可以有单独指令。必须执行的规则应放指令文件，记忆只是辅助召回。ChatGPT Work 又是不同的记忆设置，不能混为一谈。
- [Claude Code 记忆文档](https://code.claude.com/docs/en/memory)：用户/项目说明文件与按仓库自动记忆分层，后者并非把任意项目对话共享给所有项目。
- [ZCode Memory 文档](https://zcode.z.ai/cn/docs/memory)：项目记忆可延续到同项目新会话，默认关闭、忽略一次性细节、项目隔离；跨项目通用规则可用用户级指令，而不是混合各项目私人对话。

## Minion 现有基座

1. `TaskState` 持久保存当前任务原始要求、补充、断点、工具证据与子 Agent 结果；每轮控制上下文都包含当前任务，最新用户补充优先。任务状态不是全局记忆。
2. 自动压缩输出八字段结构化检查点，失败/缺字段不替换；原始消息保存在不可变事件记录并可按需检索。压缩摘要只是当前会话工作上下文，不提升为跨项目事实。
3. 项目记忆以本项目 `.minion/memory/entries/*.md` 保存，每条有类型、来源、时间、项目、核验状态；未核验不会自动召回。历史消息仍只能在本会话按证据检索。
4. `Knowledge` 已允许用户显式连接一个跨项目只读共享资料目录；它不是其他项目的对话库。

## 本轮新增

- **新会话核心短索引**：首次模型请求最多带入 6 条本项目已核验记忆和 4 条已核验的全局个人身份/偏好，每条最多 120 字，并带 ID、类型/来源。全局短档案在后续工具轮次仍会限量注入，以免长任务中消失；本项目的其他细节则按任务关键词检索。不把完整记忆或其他项目对话塞入 1M 上下文。记忆是参考资料，不能覆盖当前用户要求。
- **可控候选提取**：本项目 `Memory(action=auto_extract,mode=on)` 须当前真实用户明确要求且通过高风险确认；默认关闭。开启后，只从单条不超过 400 字、明显含“记住/以后/今后/每次/始终/默认”的真实用户输入提取候选，跳过明显含密码/密钥的文本。候选仅在项目目录保存为待核验，`Memory(action=verify,id=...)` 审核后才可用于未来会话；不调用额外模型，也不把任务自述或工具输出提升为永久事实。`mode=off/status` 可关闭/查看，`list/edit/forget/unverify` 可管理。
- **显式跨项目个人偏好**：仅把本项目**已核验**的 `user` 或 `feedback` 记忆经 `Memory(action=share,id=...)` 复制到应用目录 `.minion/memory/global-entries`，先处于待核验；再次 `global_verify(id)` 后才能在其他项目召回。`global_list/global_search/global_forget` 可查看、查询、删除。共享/核验/删除都要求当前真实用户消息明确提及跨项目或全局意图，且仍走高风险确认；模型编造的 USER 提示不能授权。项目事实、原始聊天和子 Agent 工作记忆不得进入此层。
- **全局个人档案直录和开关**：无需先创建项目记忆，用户明确要求后可 `global_remember(type=identity/user/feedback,content=...)` 直接保存**待核验**身份/偏好；用户另外明确说“确认/核验这条全局记忆”并审核后，`global_verify(id)` 才允许新项目/新会话读入短索引，不能把“保存候选”等同于“审核通过”。`global_edit` 修改后重新待核验，`global_unverify` 立即停用，`global_forget` 删除。`global_generate(mode=on/off/status)` 控制从真实用户直接输入中提出身份/偏好候选，默认**关**；`global_use(mode=on/off/status)` 独立控制跨项目注入，默认**开**（仅已核验条目能注入；与 Codex 全局默认关不同）。自动提取只识别极少数直接身份/偏好句式，不调用大模型，不从工具/子 Agent/项目私人历史抽取，候选需人工核验后才使用。显式全局更改须当前真实用户要求并经高风险确认。包含明显凭据、路径、内网/客户/合同等文本禁止写入全局层。
- 修正 `Memory` 旧 Markdown 入口跟随当前 `cwd` 的问题：现在固定到工作区根目录，避免 `cd` 后新会话读到另一份“项目记忆”。

## 使用方式与验证

1. 先 `Memory(action=status)` 查看状态；默认不开自动提取。明确需要时说“开启本项目自动记忆候选提取”，然后审核 `Memory(action=list)` 的待核验条目。也可以手工 `remember(type=user/feedback/project/decision/reference,content=...,source=...)`。
2. 用 `verify(id)` 让可信条目参与同项目后续会话的短索引；错误或过时内容先 `edit`（自动降为待核验）或 `forget`。项目文件更新后，旧决定仍需重新核验，不能只信记忆。
3. 若某条**个人偏好**确实适用于所有项目，由用户明确要求跨项目共享，先 `share(id)`，检查 `global_list`，再 `global_verify(id)`；身份/偏好也可直接 `global_remember`。不共享项目路径、内网资料或私人对话；这类资料如需共用，应由用户显式连接 `Knowledge` 共享目录。若想逐步自动形成个人档案，先由用户明确开启 `global_generate`，定期审核待核验项；不想在新会话使用时关闭 `global_use`。
4. 回放场景：同项目新会话继承已核验索引；未核验不注入；不同项目看不到项目记忆和私人对话；只看得到显式核验的全局偏好；新用户要求覆盖旧记忆；连续压缩后原文仍可检索；手工改 Markdown 正文后自动失去核验状态。

限制：窄规则候选提取可能漏掉隐含偏好，也可能提出无价值候选，因此只提议不自动核验。当前候选在用户直接输入安全入档后同步生成，**尚未实现 Codex 的空闲延迟后台提取/模型辅助归并**。规则型敏感信息过滤也不能替代全面脱敏。完整的冲突消解、来源失效自动检测与内网真实模型回放尚需后续验证，不能靠“1M 窗口”替代。
