# 本地绘图与模型能力

## 先区分两种“生图”

- **专用图像模型生成**：直接生成写实人物、风景、复杂绘画等图像，需要独立图像模型/服务。
- **代码绘图**：聊天模型设计构图、文字和代码，本机工具实际绘制图片。适合流程图、数据图表、业务信息图、封面、排版海报。

DeepSeek V4 Pro/Flash 不是专用图像生成模型；公开接口的输出模态为文本。Qwen3.8-Flash 官方说明是文本/图像/视频输入、文本回答。能接收图片不等于能输出图片；内网实际视觉能力还取决于具体部署，不能依据模型名字自动假定。

参考：[DeepSeek 模型模态](https://api-docs.deepseek.com/api/list-models/)、[千问文本生成与视觉理解](https://help.aliyun.com/zh/model-studio/text-generation-model)。Minion 不会因新绘图工具而连接这些公网地址。

## 目前的本地实现

- 现有 Python/Anaconda + Matplotlib/Pillow 继续可用；统计图以真实数据为准，保留分析脚本与口径。
- 新增 **Artwork**：Java 8 自带 Java2D / ImageIO，本地渲染，无需 Python、Chrome、GPU、外网或额外模型。不执行任意脚本，不加载远程字体/CDN。
- **ViewImage** 是读图，不是生成图像。Artwork 不自动附图给模型，避免纯文本部署因此报错；当前模型已实际确认支持视觉时才进一步看图，且不自动换主/子 Agent 模型。

## 日常使用

可以直接要求 Agent：

> 做一张16:9的业务流程图，中文、深蓝青绿色、清晰留白，使用本地绘图；输出高清PNG，并保留可编辑源稿。以下是步骤……

> 把这份Excel的真实统计结果做成图表和一页信息图，注明单位、口径与来源，不要用示例数字代替。

内置 `visual-design` 技能会引导以下流程：用途/尺寸/精确文案 → 可编辑源稿 → 布局检查 → PNG/SVG → 条件允许时看实际图片 → 只修改需要调整的部分。

## Artwork 动作

1. `help`：查询格式；`fonts`：检测本机可显示中文的字体。
2. `template`：`path=design.json, template=cover/process/dashboard`，可加 `title/subtitle`。模板只是起点，示例数据不是统计结论。
3. `Read/Edit`：修改 JSON 源稿中的文字、坐标、颜色、字号、背景和图层。
4. `inspect`：`path=design.json`，检查缺字、文字溢出、画布越界，不写文件。
5. `render`：`path=design.json, outputPath=design-v1.png, scale=2`，生成 PNG、同名 SVG 和 `.artwork-report.json`，原 JSON 保留。

默认 1600×900 源稿导出 3200×1800 PNG；用 1920×1080 源稿、scale=2 可导出 3840×2160。SVG 可缩放编辑，但文字依赖查看机器的字体。像素变多不会凭空增加照片细节。

图层支持 rect、ellipse、line（含箭头）、text（中文换行/对齐）、image（本地图片 contain/cover）。支持圆角、渐变、透明背景和图层透明度；本地素材会嵌入 SVG，复用素材不重复嵌入。素材路径相对 JSON 目录，不能用 URL。

## 质量与限制

- 缺字、文字溢出或越界须先修正，不以“文件生成成功”代替设计验收。报告 `visualReview=not_performed` 表示没有进行模型视觉审美检查。
- 当前模型不支持视觉时，不发送图片给它，也不谎称已经看过成图；用户可以打开 PNG 预览。
- 修改源稿后导出 `-v2/-v3`，默认拒绝覆盖已有源稿、PNG、SVG或报告。素材总量与最终像素有内存预算，超限时先裁剪缩小或分图。
- 代码绘图不等于扩散生图；没有独立图像模型时，不承诺照片级人物/场景或复杂绘画效果。
- 本地绘图已合入 V44 小更新，适用版本和步骤见[发布说明](releases/V44-压缩续接与本地绘图小更新.md)；Win7 内网真机仍须验证实际字体与模型调度。
