# V51 拖动排序与会话草稿隔离

日期：2026-11-08。基于本地 V50；本轮仅主 Agent 开发，没有制作更新 ZIP、推送 GitHub 或覆盖已有安装目录。

## 使用方式

### 项目与对话排序

- 拖动**项目标题到另一项目标题**的上半部/下半部，调整整个项目的位置。
- 拖动**对话到同项目的另一对话**的上半部/下半部，调整对话位置；蓝线提示插入位置。
- 可用右键“上移/下移”，或选中后按 **Alt+↑ / Alt+↓**，作为等价的键盘入口。
- 排序按完整项目/对话元数据计算，不用搜索结果或“显示更多”的扁平行号当磁盘顺序。
- 不跨项目搬动对话；项目树不接受外部文本冒充内部排序手势。同名、同 ID 的不同项目对话仍按各自句柄隔离。
- **置顶优先**：置顶分组内可手动排序，普通分组内可手动排序；不通过拖动偷偷改变置顶状态。已归档会话先取消归档再排序。
- 排序不打开历史正文、不切换执行目录、不清空聊天区、不停止后台任务。

### 最新运行自动上移

沿用并补齐原有调度入口：新任务、队列任务、计划任务、单子任务恢复等开始执行时，上移所属项目中的该会话；成功回答模型提问后也上移。

置顶仍优先。因此最新运行的普通会话位于**所属项目普通对话的第一位**；最新运行的置顶会话位于置顶分组第一位。只点击查看、展开项目、加载正文不触发上移。项目之间仍保持手动顺序，不跟随后台任务来回跳动。

手动排序会保存；下一次实际运行可以覆盖该会话在分组内的位置，这是明确的交互规则。

### 输入框草稿隔离

- 每个已选中的会话独立暂存未发送文字、图片、文件附件、命令/技能块、长文本粘贴块及其编号、光标/选择区和滚动位置。
- A输入后切到B，B不会继承A的内容；切回A恢复A的草稿。跨项目同 ID 也不共享。
- 同一次程序运行中，关闭页签不删除会话，重新打开可恢复该会话草稿。
- 切换后 **Ctrl+Z / Ctrl+Y 不会把另一会话的文字带回来**。为隔离撤销记录，切换时重置共享编辑器的撤销栈；不会保留切换前的逐步撤销历史，但保留当前完整草稿。
- 发送/回答成功后的清空只作用于当前会话，不复活已经清空的旧草稿，也不清空其他会话的草稿。发送失败/问题状态变化的原保留逻辑继续生效。
- 草稿只在**本次程序运行的内存中**暂存，不写入原会话、事件日志、项目记忆或模型上下文；不承诺退出程序后的草稿恢复。
- 尚未归属任何会话的空白输入页是临时输入，切换项目/进入其他会话时不自动转移给新会话。

## 原因与实现

原输入区复用同一个 TextArea。旧绑定先改变会话引用，再排队清理输入；快速切换或迟到回调存在“会话已经变了，文字还是旧的”窗口。直接清空也不能提供往返切换时的草稿恢复，且编辑器撤销栈必须一起隔离。

现在：

1. FX线程内同步完成“保存旧草稿→切换所有者→恢复新草稿”；其他线程只提交整个绑定，不提前改所有者。绑定代次丢弃过期切换请求。
2. 草稿以会话句柄为键，弱引用缓存不把已删除会话永久留在内存。草稿不持有 JavaFX 节点，附件共享已有不可变字符串，不反复复制整张图片。
3. 恢复过程中暂停粘贴块协调/补全解析，避免恢复文本触发块删除；使用 setText 重置跨会话撤销栈。
4. 延迟补全同时核对会话、绑定代次和确认时的原文；统计/压缩等迟到回调不能刷新另一会话的输入状态。
5. 原会话顺序文件继续使用；会话上移、拖动和读取顺序共享短锁，避免后台排队任务上移与手动排序交叉写入。显式拖动保存失败时不提交新的内存顺序。

只读参考了本机 zcode-server 的 v4 composer scope/draft store 与独立项目排序思路；没有修改 zcode-server，也没有复制其浏览器存储、引入 Electron 或新增依赖。

## 兼容与变更范围

- 仍为 Java 8 / JavaFX 8，保持现有 Win7 技术基线。
- 项目排序写原 `workspace.json`；对话排序写原 `session/<项目名>/session-order.txt`。不创建新会话数据库，不迁移/合并原项目、会话、事件或历史归档。
- V50的旧版双列表入口保留；旧列表拖动也改用本地句柄，避免跨项目同 ID 误选。
- 排序、草稿暂存不需要加载未打开会话的完整正文。已有会话的明确打开/发送仍沿用此前的兼容和持久化逻辑。
- 150K压缩阈值、模型规则、Python数据工具及原任务续接策略没有因本轮而变更。
