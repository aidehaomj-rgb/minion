# Minion V23：任务队列与多 Agent 压缩

适用：已安装 V22 的 Windows 7 / Java 8 离线版。增量更新不替换模型配置、知识库、会话文件或 JDK。

## 本次实际实现

1. **Queue 与 Steer 分开**。运行中输入并发送，默认加入本会话队列。当前任务正常结束后自动作为新任务执行；点击“立即引导”才转为当前任务补充。图片一同排队。切换会话不丢队列，队列单独落盘，重启后可查看并决定是否继续。失败/中断时保留队列，不自动越过失败任务。`/queue` 查看、`/queue remove N` 删除、`/queue clear` 清空。
2. **任务控制记录独立于摘要**。会话保存 taskState：原始用户目标、补充要求、最近进度、主任务清单、子 Agent 分工与状态。自动压缩和 `/compact` 都使用同一份当前记录，每次模型请求都带当前记录。旧摘要不能覆盖它。队列中的任务不注入当前目标；派发下一项时明确创建新任务 ID。
3. **子 Agent 状态隔离**。子 Agent 的 TodoWrite 不再覆盖主 Agent 清单；不能访问主会话 Context 工具。`task.prompt` 的补充要求/返回格式现在实际传入子 Agent。每个子 Agent 有独立上下文管理和压缩，窗口跟随本会话有效配置。超限和连续空响应可在子 Agent 内独立恢复。
4. **子 Agent 可追溯**。各子 Agent 有唯一 ID、分工、状态和记录文件。返回状态为“待主 Agent 核对”，不等于主任务完成。记录位于工作区 `.minion/subagents/<会话ID>/`；压缩前消息另存快照，索引保存在当前记录的 archives 中。中断/失败不伪装成完成；重启后旧 running 状态改为待核对。
5. **长输出按需读取**。超过 8000 字符的工具输出保存到工作区 `.minion/tool-results/<范围>/`。模型收到首尾预览和实际文件路径，需要详情时用 Read 分段读取；界面仍显示原始工具结果。写文件失败时保留原始输出，不静默丢证据。
6. **状态检查**。`/task` 或 `/agents` 显示当前目标、补充、任务清单、最近断点和子 Agent 记录。新增任务状态的 token 开销纳入主上下文估算。修复控制记录导致“摘要模型失败却被当作压缩成功”的情况。

## 压缩仍然做什么

- V22 的安全窗口、用户设置阈值、输出预留、实际 token 校准和超限恢复继续保留；没有新增固定 43K/50K 停止线。
- 压缩模型合并旧摘要与新增历史，保留近期工具调用/工具结果配对。当前任务控制记录单独保存，模型不能用摘要改写它。
- 保留区过大、服务端返回空包或显式超限时使用强制缩减；无法释放上下文则明确报错。压缩不是扩大模型服务端窗口。
- taskState 的模型进度描述、子 Agent 返回结果仍需工具证据核对；客户端不能保证模型完全不幻觉。本次测试使用本地脚本化模型与模拟服务，未直接连接内网千问服务。
- 子 Agent 仍共享工作区文件与主会话模型客户端。分工应指定不同输出文件/行范围；本次不提供工作树隔离、不自动重新启动中断子 Agent，也不声称实现完整 Agent Teams。
- 工具结果及子 Agent 归档不会自动删除；长期使用可归档已结束项目，别在任务尚需回溯时清理这些文件。

## 参考官方功能及后续建议（未在本次全部实现）

OpenAI 官方区分 Queue（下一回合）与 Steer（当前运行中补充），并介绍持久目标、旁支对话。本次实现队列/引导分离及持久任务控制记录：[Codex 官方说明](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)。

Claude Code 子 Agent 使用独立上下文和工具权限，并支持子 Agent 独立压缩/恢复。本次实现清单/上下文隔离和独立压缩：[Claude Code 官方子 Agent 文档](https://code.claude.com/docs/en/sub-agents)。

CodeBuddy 官方提供专职子 Agent、工具限制及独立模型配置。本次借鉴明确分工与状态可追溯：[CodeBuddy 官方子 Agent 文档](https://www.codebuddy.ai/docs/zh/cli/sub-agents)。

建议下一阶段按顺序做：

- 只读探索 Agent 与工具白名单，减少无意修改；
- 子 Agent 独立模型选择与用量统计；
- 并行写同一文件的冲突检测/隔离工作目录；
- 子 Agent 指定 ID 的人工断点恢复与可视化任务面板；
- 不干扰当前目标的旁支提问。

这些是后续候选，不属于本更新包已实现的功能。

## 更新

关闭 Minion，解压更新包，运行 `Update-Minion-V23.cmd`，输入原安装目录，确认更新。
脚本只替换 JAR 中列出的 class，保存 `backup/minion-0.1.0.jar.pre-v23-*.bak`。
更新失败会恢复刚才备份的 JAR。模型配置及所有项目数据均不修改。

如需手动回退：关闭 Minion，将这次 `pre-v23` 的备份复制为原目录的 `minion-0.1.0.jar`。
不要选旧版本通用 rollback 的更早备份，避免回退到不匹配的历史版本。
