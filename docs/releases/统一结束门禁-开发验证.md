# 统一结束门禁（已收录V30更新）

## 改了什么

这次替换“某句回复看起来结束了”的放行机制，不继续扩充词汇表。一次模型响应结束不再直接意味着任务完成：主Agent和子Agent的正常拟结束回复必须经过独立、只读的小请求，结合当前用户目标、最新补充、待办、子任务状态、登记文件和真实工具收据验收。

- `completed`：控制面无缺项、证据引用合法，才允许正常结束并运行已有后续任务队列；实际操作任务需要成功工具收据。程序给主任务交付附完成时间。
- `continue`：明确缺项与下一步，返回原执行流程；原权限和确认流程不变。普通文本回答不强制升级成文件/工具任务。
- `waiting_user`：需要资料、权限或选择时保留断点，等待用户，不假称完成。
- `unknown`：证据不足、协议错误、非法JSON或审核网络异常时明确暂停，后续队列保留。

未完成Todo、未核对/运行中/失败的当前子Agent和登记断点的缺失/变更/越界文件，不能被模型的完成声明绕过。文件哈希证明版本，不证明业务结论正确；合法更新仍须先复核，再refresh_checkpoint（带说明）或重新登记完整checkpoint。

审批与任务ID、快照版本、单次票据绑定。检查期间收到新补充或证据变化，旧审批作废；主动停止后不自动复活。新任务不使用旧任务工具收据。主/子审批与预算独立，子任务完成不批准主任务完成。

## 请求与成本

使用会话当前配置的模型，不另外接入外部服务。通常拟结束时增加一次无工具、非流式请求：禁用思考，输出上限1024token，单请求30秒超时，响应最多64KiB。只有结构校验失败最多再请求一次；有效的unknown和网络错误不反复重试。超时取消只作用于审核请求，不取消共享客户端的其他执行请求。

输入上限48,000字符（不是token阈值）。只保留最多24个近期实际工具收据预览（参数500字符、结果1200字符）、最多12个已登记且有权限的文件事实、少量指代参考及本轮先前交付段落。不另读全段历史、不把工具/回复正文当审核器的新指令。成本统计包含审核请求。

无进展续接通常最多12次；带旧完成标记但控制面/验收仍拒绝的收尾最多3次。status/verify、失败工具和相同工具结果不会清零；新成功工具事实可继续。预算用尽显示原因、保留断点，不标完成。

## 保留与限制

保留V29及之前的完成时间、断点刷新、模型配置、自动/手动压缩、共享知识库、历史分页、数字提问回答和并发文件保护。本次不改变上下文上限、压缩阈值或单次执行输出上限；已发布V29压缩包未修改。

这是机制改进，不是模型永不错误的保证。结束评估仍使用同一模型，可能语义错判；成功收据也不自动证明与目标相关。文本/工具预览或指代被截断、遗留会话缺少范围明确的工具台账时可能unknown，需要实际补验，不允许拿旧任务假证明。不断产生不同但无关工具结果的循环不保证被预算识别，原轮数和流式循环保护仍保留。

当前`sfm-agent`远程执行会话不能安全承载隔离核验，显式返回unknown，不向其执行会话注入审核指令；DeepSeek/Qwen等OpenAI兼容聊天接口走此实现。第三方LlmClient实现若覆写审核接口，也须遵守独立请求、有限超时和只读约束。

失败/被中断子Agent仍需重试或主Agent明确向用户说明，不能直接用review把失败改为完成。少量指代参考只帮助解释当前“按这个/按方案”，不能复活旧目标。
