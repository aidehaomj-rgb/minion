# Minion V24：V23 + 多 Agent 工作流合并更新

本包可从 V22 直接升级，**不需要先安装 V23**。使用原离线程序的 Java 8 / Win7 运行环境；不替换模型配置、项目、技能、知识库和历史会话。

## 包含 V23 内容

- 待引导内容默认进入队列；点击“立即引导”才补充当前任务，未点击的内容在当前任务成功完成后作为新任务发送。暂停/失败时队列保留，不串入旧任务。
- 当前目标、用户补充和主任务清单独立保存，自动压缩与 `/compact` 不允许摘要替换这些控制记录。
- 子 Agent 分工、清单、压缩和记录隔离；主 Agent 必须核对结果后汇总。大工具输出落盘，模型按实际路径分段读取，原始本地历史不删除。
- V22 的历史查看、共享知识库连接、会话内模型选择、上下文安全窗口和恢复逻辑继续保留。

## V24 新功能

1. **文件冲突保护**：Minion 进程内的修改工具串行执行；只读文件工具与模型请求仍可并行。共享知识库跨项目也使用同一写入锁。直接 Write/Edit 前比较上次读取的文件哈希；文件已被改动则拒绝旧版本写入，要求重新读取和合并。子 Agent 修改已有文件必须先 Read。Shell/Python/插件等未知操作也保守串行处理，不能自动判断其是否只读。
2. **证据断点**：主 Agent 可调用 `AgentControl(action=checkpoint, nextStep=..., processedRange=..., files=...)` 登记处理范围、下一步和实际文件（换行/分号分隔路径）。保存大小和 SHA256；`verify` 或面板按钮可检查文件变化。声明完成时若登记文件已变更/缺失，不会把当前轮标为成功或自动派发后续队列。存在/哈希核验不是业务正确性认证。
3. **子 Agent 恢复**：每个子 Agent 有 ID、模式、模型、状态、用量和记录。面板可以单独停止，主任务空闲后可恢复或重试。恢复保留已完成工具结果、分工和子任务清单，清除残缺工具调用，要求先核对文件、只补缺项；重试从分工重新开始，旧记录先归档。重启不自动执行子 Agent，避免重复写入。
4. **只读探索与白名单**：`task` 新增 `mode=explore/worker`、`allowedTools`（逗号分隔）、`model`（已有模型配置标识）。explore 仅允许 Read/Glob/Grep/Knowledge 的 search/list/read，以及本地子任务 TodoWrite；禁止 Shell、Python、写入及未知插件，运行时再次拦截，不能靠隐藏按钮绕过。worker 仍受工具授权约束，权限/Secrets/Update/主会话 Context 等管理工具对子 Agent 禁用。
5. **任务面板**：对话顶部、报告按钮旁新增“任务”。包含主任务与断点、子 Agent、上下文预算、队列、旁支提问五页，可暂停/继续主任务、查看子 Agent 记录位置、登记核对、取消指定队列项。面板固定绑定打开时的会话，不会跟随切换误操作别的会话。
6. **节省上下文**：发送副本去除重复大工具结果，保留最新一份；不会删除原历史或改变 tool_call_id 配对。balanced 保留较多工具输出，compact 对工具输出和旧思考使用更小预览；目标/已加载技能不按这些工具限额截断。知识库先 search，再 read 命中条目；不自动把全库装入每个请求。预算显示任务、技能、摘要、正文、工具、思考、图片与工具定义的估算组成。
7. **独立子模型**：任务面板中的默认子 Agent 模型只影响当前会话今后的分工；已有子 Agent 恢复时仍保留原模型。每个 GUI 子 Agent 使用独立客户端和 cwd，可单独取消，不取消主模型请求。子 Agent 的上下文与累计输入/输出单独统计；API 没返回 usage 时标注估算。
8. **旁支提问**：在面板单独提问，仅携带最多 6000 字符的任务背景，使用独立连接、不提供工具、不注入主任务历史，也不修改目标和清单。答复单独保存在 `.minion/side-questions/<会话ID>/`，可查看近期提问历史。

## 怎么使用

- 升级后打开会话，点击顶部 **任务**。子 Agent 页可选默认模型、worker/explore 和工具白名单；保存只影响这个会话。
- 模型也可以在 `task` 工具每次分工时明确指定参数。分工应指定不同文件/行范围，先探索后执行，主 Agent 核对工具证据后 `AgentControl(action=review,childId=...,note=实际核对说明)`。
- 子 Agent “恢复”不是重跑主任务；先暂停主任务并等待结束，再选中失败/中断子 Agent 恢复。核对已返回结果可在面板登记说明。重试有二次确认。
- `/budget` 查看最近一次请求预算；`/agents` 查看当前分工；`/agent stop|resume|retry <完整ID>` 控制单个子 Agent。
- 上下文页的安全窗口 0=自动；可指定 8192 到该模型配置上限之间的值。服务端实测超限后仍会收紧。确认服务端容量已增加、会话空闲时，可点“重置学到的窗口”。本地 131K 配置不是服务端容量证明；没有新增固定 43K/50K 停止线。

## 边界

- 不提供 Git worktree 文件隔离或跨程序文件锁。外部程序仍可能同时修改文件；Shell/Python 的语义冲突不能用 Write/Edit 的读取哈希规则完整识别。禁止多个 Agent 随意覆盖同一成果，仍需明确分工。
- 恢复提示和证据记录降低重复/跑偏风险，但不能保证模型永远不幻觉。不要把子 Agent 的“已返回”当成主任务完成。
- 已返回但尚未登记核对的子 Agent 会触发主 Agent 补充核对，最多两轮；仍未核对则暂停并保留队列，避免无休止消耗。失败子 Agent 需主 Agent 另行补齐或说明缺项，不能把 review 当作执行成功证明。
- 工具输出、子 Agent 归档、旁支记录不会自动删除；长期使用可按项目人工归档。旁支问答不具备文件读取能力，不等同于完整任务分叉。
- 测试使用本地脚本化模型与模拟 HTTP 服务。没有连接你的内网服务，也没有在你的 Win7 电脑上实测；保持原 Java 8 离线环境。

## 安装与回退

关闭 Minion，解压本包，运行 `Update-Minion-V24.cmd`，输入原安装目录并确认。脚本校验补丁哈希、备份旧 JAR，应用后验证 `com.minion.Boot` 入口；失败自动恢复刚才的备份。

此包只携带 Minion 应用类和主题资源，不携带第三方库/JDK，因此远小于完整约 20MB 程序。备份为原目录 `backup/minion-0.1.0.jar.pre-v24-*.bak`。手动回退时关闭程序，将**这次 pre-v24** 备份复制回原 `minion-0.1.0.jar`，不要选更早的通用 rollback 备份。
