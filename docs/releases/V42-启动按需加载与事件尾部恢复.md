# V42：启动按需加载与事件尾部恢复

## 定位到的瓶颈

V40 在窗口出现前遍历所有项目：`SessionStore.list()` 先完整解析每个快照，随后 `restoreSessions()` 又加载一遍；每个会话还恢复全部原始事件、逐条重新 SHA-256、建立客户端/工具和 UI 事件副本。启动时间随旧会话、事件和图片数据总量增长，而非只随列表条目数增长。

## 实现

- `.session-index` 保存标题、时间、预览、模型标识、置顶/归档等小字段；按快照长度/修改时间判断缓存是否失效。不存在或损坏就流式重建，不改变原快照。外部更新的快照自动重建相应索引。
- 启动恢复轻量 `SessionHandle`，不读完整消息、不重放事件、不建立 LLM/工具运行时。打开、发送或实际修改该会话时，才加载其完整数据并恢复队列。列表占位对象禁止持久化覆盖原正文。
- 删除未打开会话不必加载它。设置刷新跳过未打开会话，首次打开时使用最新模型配置。模型选择、工作空间重命名、归档、置顶和手动顺序继续保留。
- 事件日志只枚举序号，并校验/重放快照之后的尾部；已提交到快照的旧事件不在每次打开时全量读取/重算哈希。用当前工作上下文初始化消息去重表，保留追加事件和压缩恢复语义。原始记录不删除；不承诺启动时发现所有旧记录损坏。
- SHA-256 十六进制编码改为直接字符映射，去掉每个字节一次 `String.format`。
- 过期临时文件清理移到后台低优先级线程；列表排序预建 ID→位置映射，避免比较器反复线性搜索。
- 保留原子保存和未提交尾部校验，不增加额外联网、模型检查或全盘扫描。
- 包含 V41 绿灯修复，直接从 V40 更新；V41 未安装时不必补装。

## 离线合成基准（本机，Java 8）

使用 `tools/win7-updater/StartupBenchmark.java`，20 会话、2400 消息/事件、11,928,570 字节快照。运行同一组合成数据，模型客户端用不会联网的桩代替，衡量 `SessionManager` 构造（不含 JavaFX 主窗口和 JVM 启动）。

| 版本/条件 | 会话初始化 | 启动创建客户端 | 首次打开一个会话 |
|---|---:|---:|---:|
| V40 | 38,540ms | 20 | <1ms（已全部预载） |
| V42 首次建立索引 | 397ms | 0 | 964ms |
| V42 索引命中 | 266ms | 0 | 890ms |

这是一次合成测试，不是内网 Win7 上的性能承诺，也不是完整 GUI 的端到端耗时。首次升级需要建立索引；点开超长会话仍有一次性加载时间，但不会让所有历史拖慢每次启动。

## 验证范围

验证惰性恢复、打开后原文/队列完整性、未打开会话重命名/置顶/删除、加载失败不得覆盖快照、设置刷新不物化其他会话、索引损坏/外部文件变化、尾部崩溃恢复、消息去重及修改后追加，以及现有 Agent/压缩/历史回归。

启动日志位于安装目录 `.minion/logs/minion.log`，新增会话列表初始化与主窗口构建耗时；单个会话加载另记 `session-load`。
