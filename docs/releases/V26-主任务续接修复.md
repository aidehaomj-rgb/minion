# Minion V26：主任务未完成时自动续接

## 问题与修复

用户日志显示 DeepSeek-0731 在输入75976 token时正常返回 `stop`、无工具调用；主任务仍需核对子Agent并继续派发，但客户端直接执行了 `model_response_end`。这是一次回复结束被误作任务收尾，不是上下文超限。

- 识别“继续推进。先验证…”、“让我检查…”、“让我核对…”等明确的末尾下一步意图，包括长分析后的计划。工具任务遇到这些回复会要求立即落实为工具动作，而不是直接退出。
- 无工具调用的回复统一先检查当前任务的未完成待办、运行/失败/中断/待核对子Agent，以及变更或缺失的断点证据。不再只有模型已经报告成功时才做证据检查；误报完成标记也不能绕过未完成状态。
- 有子Agent或结构化任务清单的主任务，短回复同样需要最终交付确认。子Agent返回、核对一块或保存执行记录均不等于整个主任务完成。
- 主Agent提示增加多块/多批任务先登记完整范围与最终汇总核验，再按实际结果勾选待办，防止只完成首块就丢失剩余范围。
- 明确缺少资料、等待用户确认/授权时保留断点并暂停，不自动替用户决定。普通问答和简单工具查询不会被强制要求复杂任务完成标记。
- 未完成状态、交付确认与阶段性正文统一使用最多12次连续无动作续接上限；实际工具调用后计数归零。不因阶段性正文强制压缩健康的上下文。不保证所有模型故障都能自动恢复。
- 增加 `agent-continue` 和具体退出原因日志；未通过任务检查的回复即使带完成标记，执行报告也不会标为模型已完成。完整本地历史和任务锚点保留。

## 安装

这是应用类小更新包，包含V23～V25功能，可从V22/V23/V24/V25离线版升级，不替换JDK、第三方依赖、模型配置/API Key、项目、技能、知识库和会话。不改变V25压缩阈值或Qwen经验安全窗口逻辑。

1. 完全关闭Minion。
2. 解压本包，运行 `Update-Minion-V26.cmd`，输入原安装目录并确认。
3. 成功后重新启动，打开原会话，发送一次“继续执行之前未完成的任务”。已停止的旧任务不会仅因安装更新而自动开始。

安装前自动备份旧JAR；失败恢复本次备份。需要手动回退时，关闭程序，将本次 `backup/minion-0.1.0.jar.pre-v26-*.bak` 复制回 `minion-0.1.0.jar`。不要覆盖或删除会话文件。
