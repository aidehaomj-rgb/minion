# Minion V25：自动压缩阈值 + V23/V24 合并更新

无需先安装 V23 或 V24，可从原 V22 离线版直接升级。包含 V23 的任务锚点、引导队列、子 Agent 独立压缩，以及 V24 的任务面板、证据断点、子 Agent 恢复、权限/模型选择、预算和旁支问答。包内附有完整 V24 功能说明。

## 本次修改

- 设置 → 模型 → 选中模型 → 修改：新增清晰的 **自动压缩阈值 (%)** 和预计触发 token 数。按模型保存，使用该配置的主会话和新建/恢复的子 Agent 均按此比例判断。编辑后下一轮生效，无需重启；运行中的子 Agent 保持它启动时的配置。
- 原来的 `compressThreshold` 字段仍保存为 0~1，旧 0.8 自动显示为 80%，不需要迁移或重新填写 API Key。
- 删除隐含的“固定预留窗口20%”上限，90%/95%设置不再被强制压回80%。保留输出预算：触发线取“窗口×比例”与“窗口减单次输出余量”的较小值，常见窗口至少预留8192 token。比例很高时显示的实际线可能低于比例线。
- 实际模型名不是 Qwen3.8 时，不套用旧 Qwen 60K 经验安全窗口，即使配置标识沿用了旧千问名称。换到另一个模型时清除旧模型的手动/实测安全窗口；只修改同一模型的阈值时保留本会话手动窗口。
- 输入错误不再默默回退默认值：比例必须大于0且不超过100，窗口至少8192，单次输出256~65536且小于窗口，消息数不能为负。输入圈提示使用真实自动压缩线。
- `/compact`、当前任务锚点、完整本地历史和超限/空响应恢复机制继续保留。没有改为无限重试，也没有把客户端1M配置当作服务端容量证明。

## 新 DeepSeek 内网模型怎么设置

1. 设置 → 模型 → 新建或修改对应配置；模型名填内网服务实际接受的 `deepseek-v4-flash-0731`，URL/API Key按原内网配置填写。
2. 若管理员确认部署窗口为1,000,000 token，窗口填 `1000000`；若部署采用1,048,576，填 `1048576`。不要仅凭模型名称推断。
3. 自动压缩阈值可先填 `90`，单次输出仍为 `8192`：1,000,000窗口的比例触发线为900,000；也可按需求填80、85、95等。
4. 对话输入区选择这个模型，仅切换当前会话，不改其他会话的模型选择。
5. 如果已经使用该模型且旧会话曾学到较低窗口，确认服务端确已增加后，打开“任务 → 上下文预算”，将安全窗口设为0（自动），保存，再于会话空闲时点“重置学到的窗口”。后续服务端真实超限/连续空响应仍可能触发提前恢复压缩；不是固定60K阈值。

此修改不增加服务端实际窗口，也不保证1M请求延迟或质量。没有访问你的内网服务，测试使用本地脚本化模型和模拟接口。

## 安装和回退

关闭 Minion，解压后运行 `Update-Minion-V25.cmd`，输入原安装目录并确认。只更新应用类和主题，不替换 JDK、第三方依赖、API Key/模型配置、项目、技能、知识库或会话。更新前备份旧 JAR；应用失败自动恢复本次备份。

手动回退：关闭程序，把原安装目录 `backup/minion-0.1.0.jar.pre-v25-*.bak` 中本次备份复制回 `minion-0.1.0.jar`，勿使用更早版本的通用 rollback。
