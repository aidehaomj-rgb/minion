# Minion V27：中断误触与口头工具循环修复

## 本次问题

- 第一张截图是新任务在约0.1秒显示“本轮已被中断”，不是上下文超限。代码检查发现发送键和停止按钮共用入口：发送后输入已清空、会话转为运行态，再次按Enter或键盘自动重复会走STOP分支。本包修复这一可复现路径；不能据截图断定所有中断均来自该路径。
- 第二张截图只有反复“我现在调用Bash/先调用Bash”的正文，没有真实工具调用，最后退出。V26未识别这种末尾意图；长正文也可能只进入完成标记追问，反复追问不能保证模型落实动作。

## 修复

1. 键盘发送永远不会变成停止。空输入发送键仅消费事件；停止按钮与Esc仍正常取消，不自动重启用户主动取消的任务。
2. 发送/引导使用会话即时运行状态；延迟或切换会话后的旧界面回调不能覆盖新状态，减少重复发送与补充串轮。
3. 补全“先调用Bash/我现在实际调用工具”等末尾计划识别，包括长篇重复正文。
4. 工具任务连续两次只返回计划/未完成状态后，恢复请求明确关闭思考，并使用`tool_choice=required`要求模型返回实际工具调用。实际工具调用后回到用户原来的模型模式；普通问答与无工具请求不强制。
5. 恢复请求仍提供原工具schema，工具由模型选择，经过原有参数校验、确认和权限守卫。不会从普通正文提取并执行命令，也不会伪造工具调用。
6. 网关明确报告不支持`tool_choice`时，一次回退普通工具选择，并仅在该客户端实例记忆能力；认证、上下文超限、JSON错误和其他400不冒充能力问题重试。若网关忽略参数或模型仍不动作，保留最多12次无动作上限并提示未完成，不无限消耗。
7. 增加停止入口、中断退出、协议动作恢复日志；不因此强制压缩健康上下文。V25压缩阈值配置和V26任务检查继续保留。

DeepSeek恢复参数依据：[对话补全官方协议](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。官方协议说明思考模式不支持required/指定工具，故恢复时需明确disabled；用户内网网关能力仍以实际响应为准。

## 安装

### 同步修复长文本显示和思考折叠

- 移除界面24,000字符的头尾裁剪。正文、工具详情和思考全文保存，通过“上一段 / 下一段 / 末段”查看全部内容；“复制全文”复制完整原文。每段约12,000字符，仅当前段交给JavaFX布局，继续防止超长会话把界面拖垮。回复的Markdown只解析当前分页；跨分页的Markdown语法可能单段展示为原文，复制全文保留完整格式。
- 模型响应结束后思考自动收起（包括短思考或只有思考、无正文的响应），手动重新展开不会被后续正文反复关闭。工具详情仍保持原500字符折叠阈值。
- 明确区分每次响应结束和主任务完成；自动续接的新响应不再合并到同一显示段。历史回放恢复纯工具调用消息附带的思考。
- 这解决客户端省略；服务器真正因输出上限结束的回复仍走既有续接逻辑，不能从未收到的数据中恢复全文。模型发在正文里的口头计划仍是正文，不伪装为真实思考或执行事实。

### 数字选择回答修复

提问工具不再仅向模型回传一个裸编号。有效编号回答回传用户原文、对应问题、已选状态、选项编号/名称/说明；UI和历史输入仍显示原始回答。多选仅在该问题允许多选且所有编号均有效时展开；自由文本、越界编号及带额外限制的回答保留原文，不猜测含义。提问快照与当前等待槽绑定，空回答不提交，重复提交不能覆盖第一份回答。正常工具结果仍保留原tool_call_id配对，不新增授权或自动执行。

这是累积应用类小更新，包含V23～V26。从V22～V26升级无需逐个安装旧包，保留JDK/第三方依赖、配置、API Key、项目、知识库、技能和历史。不会仅因安装而自动启动已暂停的旧任务。

1. 关闭Minion，解压本包。
2. 运行`Update-Minion-V27.cmd`，选择原安装目录。
3. 启动后回到旧会话发送一次“继续执行之前未完成的任务”。

旧JAR自动备份至`backup/minion-0.1.0.jar.pre-v27-*.bak`。如果需要回退，关闭Minion后将本次备份复制回原JAR，保留会话文件不动。
