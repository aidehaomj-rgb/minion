# 完成后反复续跑修复（V29）

## 原因

阶段断点保存的是当时的文件哈希。最终输出按用户要求重生成后，旧断点不同并不必然代表业务未完成，但旧实现没有显式复核刷新流程。模型反复查询status并声明完成，工具调用又清零无动作恢复次数，导致同一断点差异不断触发自动续跑。

## 修复

- AgentControl status增加实时断点核验，显示具体文件unchanged/changed/missing/unreadable；查询本身不更新快照。
- 新增refresh_checkpoint，要求note说明实际内容复核和合法变更原因；重新采集全部已登记文件哈希，保留处理范围、清空下一步并记录复核说明。文件缺失或权限不允许时不更新任何原记录。不自动根据完成标记刷新，不把哈希视为业务正确性证明。
- 当前任务提示和收尾恢复提示明确指导模型在实际验证完成后刷新或重登记完整交付文件，避免盲目重跑输出。
- 独立的控制面恢复预算最多12次；完成声明仍被控制面阻塞时最多3次恢复。工具查询/动作不清零预算；最终状态全部满足时正常结束，不因已用完预算而拒绝真实完成。
- 预算耗尽明确暂停并保留记录，不伪报完成、不自动发送后续任务队列。待办、未核对子Agent、缺失文件和权限保护保留。没有改动压缩、上下文容量、模型输出限制。

## 验证

新增5项回归覆盖：合法更新复核刷新后正常完成；完成声明与status交替有界；缺失文件保留完整旧快照；必须复核说明且不能旁路待办；无完成标记时状态查询交替也有界。相关测试通过，JavaFX历史分页和聊天显示验证通过；JDK8全套回归共1268项，1265项通过、3项跳过，失败和错误均为0。git diff --check通过。
