# V50 项目→对话侧栏：设计与兼容约束

日期：2026-11-08。只修改 Minion；本机 zcode-server 只读参考，未复制其数据库或身份机制。

## 产品规则
- 新默认视图为项目→会话层级；项目展开/折叠不切换工作区、不加载历史正文。
- 标题/项目路径搜索、分页显示更多、项目内新建会话、会话置顶/重命名/删除保留。
- 导航跨项目对话先在后台准备该会话，再在当前导航请求仍有效时切换；不重新发送原任务，不停止其他项目后台任务。
- 保留旧版双列表入口；新视图偏好只写 jar 同目录 sidebar-view.json，不修改 workspace.json 的结构或 session JSON。
- 保留工作空间名称的身份，绝不按路径去重/合并，两个项目指向同一目录仍是两个项目。
- 不支持通过树拖拽将会话跨项目移动；避免擅改任务目录、记忆和事件来源。
- 缺失目录或没有会话的项目仍展示，不自动删除、补造历史或修复项目路径。
- 已归档会话保留原字段，默认隐藏，可显式查看；删除对话需确认，项目节点不提供一键递归删除。

## 状态所有者
- WorkspaceManager：项目配置和现有项目顺序。
- SessionManager/SessionStore：会话句柄、正文、存储路径、会话顺序和运行状态。
- ProjectTreeModel：只读展示投影，按项目名称+会话ID区分，不能把跨项目同名/同ID合成一项。
- ProjectSidebarView：搜索、折叠、显示数量；只通过既有/新增导航API触发明确操作。
- MainWindow：当前打开页签与视图缓存按SessionHandle关联，避免跨项目重复ID导致误绑。

## 数据不迁移
现有 workspace.json、session/<工作空间名>/*.json、事件和历史归档目录、会话排序文件不搬动、不批量重写；仅浏览项目树不得触发ensureLoaded或保存空占位会话。
用户明确打开旧会话时，沿用既有恢复与兼容逻辑；这不代表新侧栏会修改原始消息内容。

## 验收
1. 老数据两项目、多会话、中文路径、同目录不同项目、相同会话ID，均按原归属可见。
2. 读取/搜索/折叠/切换视图后，原始workspace/session/order/events/archives字节不变（不执行明确导航写入操作）。
3. 展开大量旧会话不创建模型客户端、不读取完整消息、不执行工具。
4. 跨项目点击与快速连点不被迟到加载抢焦点；新会话只创建于明确选中的项目。
5. 后台运行/等待用户/绿色未读、置顶、重命名、删除、页签关闭/重开回归。
6. 新偏好缺失/损坏不影响旧存储；新程序打开后旧版仍能读取原会话。
7. Java8/FX8离屏及真实JAR界面验证，不冒充真实Win7与内网认证。
