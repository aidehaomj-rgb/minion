# 数据分析与材料工作流（V32开发）

全部本地运行；模型请求仍发往当前配置的接口。图片/PDF视觉识别依赖该接口实际支持图像，不新增模型供应商。Python为普通本地进程，不是操作系统沙箱。不自动安装OCR/LibreOffice或上传外网。

## PDF与图片

上传PDF默认只预览前3页文字，保留来源路径；扫描页可添加，不再因文字层为空拒绝。工具读取仍检查目录授权。

Document的页码从1开始：
- `{"action":"pdf_read","path":"a.pdf","startPage":"1","endPage":"5"}` 按页文字，显示下一页和未读页。
- `{"action":"pdf_view","path":"a.pdf","startPage":"2","dpi":"150"}` 把第2页像素附入当前Agent上下文。一次一页，dpi72–200，可带x/y/width/height裁剪（渲染像素）和rotate旋转。
- Read遇PDF引导至Document，不按二进制文本解码。旧Document.extract仍仅提取文字层，不代表图表已识别。

PDF上限50MB、单页渲染1200万像素；文字单次6万字符、最多20页。超限明确提示未全部读取。文字页缓存最多32页，以实际读取的内容SHA256版本为键，改变文件后旧缓存不复用。pdf_view使用临时PNG，不修改PDF；图像超限可降DPI/裁剪。加密文件需要先经合法授权解密。

## OCR

设置 → 文档/OCR：填Tesseract程序路径、语言（默认chi_sim+eng）、可选LibreOffice程序路径；点应用。Diagnostics显示Python/Office库、OCR和预览程序可用性，不会安装。

`{"action":"ocr","path":"label.png","language":"eng","psm":"7"}` 返回TSV文字、原图坐标、引擎conf分数，并把原图附入上下文。psm3–13；引擎分数不是事实正确率。照片须为可解码图像（不支持直接对PDF做OCR），PDF扫描页先pdf_view；需OCR可通过已有Python/Bash工具在授权范围内将页面存为图片。没有识别文字不等于没有品牌。OCR/视觉冲突交给人工核对。缺语言包或坐标输出失败，工具明确失败。OCR有90秒超时和输出上限。

## 数据分析

- `Excel.read`/filter：offset从0起（不含表头），rows1–1000；报告结果总行数、下一offset和未读范围。只读/探查模式禁止含pandas.query筛选表达式的请求。
- `textColumns="报关单号,商品编码"` 强制指定列按字符串读取，保护文本前导零和长单号。源单元格已存为浮点且损失精度，不能恢复；不自动把所有数字转字符串。金额汇总用validate的valueColumn，Decimal按读入值求和；币种、千分位和业务口径需单独清洗核对。
- `merge_audit`：path、otherPath、on。全量唯一键匹配统计，重复键/空键统计，未匹配样例最多20项；空键不算正常匹配。实际merge仍按用户选择关系执行，不能将多对多行数膨胀当增加业务记录。
- `validate`：检查列、行、缺失、重复、ID唯一数、指定valueColumn合计；xlsx/xlsm扫描全部sheet、公式单元格与错误单元格。不重算公式、不证明业务口径正确。
- `patch_cells`：输入xlsx/xlsm、另一个outputPath、data为JSON字符串：`[{"sheet":"数据","cell":"B2","value":"9001234567890123456"}]`。最多20000格，重新打开核对；保存普通sheet/格式/公式，复杂绘图和控件仍须核对。长单号值必须是JSON字符串，默认以等号开头的字符串也只当资料文字；仅显式formula=true才写公式。不覆盖源文件，扩展名须保持一致，宏工作簿使用keep_vba。
- 原有导出/合并/透视是新的数据表，不能宣称保留原工作簿；需要回填请用patch_cells。大输出继续由工具结果存储落盘，按提示Read续读。

## 材料与预览

需要python-docx。`docx_template`用path指向DOCX模板、outputPath另存，data：`{"fields":{"标题":"情况报告"}}`。模板占位符为`{{标题}}`，支持跨run及表格/页眉页脚，替换保留未覆盖run样式；文本框/批注/域等特殊结构不保证处理。未替换段落明确列出。

`docx_report`可选path模板，data示例：

```json
{"title":"情况报告","fields":{"标题":"情况报告"},"styles":{"body":"Normal"},"evidence":[{"id":"E1","source":"a.pdf","location":"第2页"}],"sections":[{"heading":"核验情况","level":1,"status":"原文","evidenceIds":["E1"],"paragraphs":["经实际核对后填写的原文"],"tables":[["项目","数量"],["样例","1"]]}]}
```

章节status区分原文/分析/已核对/待核实；原文和已核对必须登记证据ID。**登记来源不是证明引用真实**，模型仍须实际读取来源。材料生成后写`输出.docx.material-state.json`，包含章节阶段、证据定位、产物SHA256和visualVerified=false，原Agent任务状态仍为权威。源文件变更后docx_validate指出状态版本不一致。

`docx_validate`检查可打开、标题、表格、占位符和待核实项；特殊文本框/脚注等需预览。`office_preview`把DOCX转新PDF，需本地LibreOffice，随后用pdf_view逐页核对页码、字体、表格和分页。转换成功不等于视觉验收。缺依赖会失败，不声称排版已核验；预览拒绝含宏/ActiveX/嵌入对象或外部关系链接的文档，使用独立临时用户配置。普通报告带超链接时也可能需先另存无外部链接的安全副本。

## 安全与兼容

输出仅在项目内，原文件不默认覆盖；回填、报告和模板写出使用临时文件替换。共享只读知识库可以通过既有放行目录读取，但不作为输出目录。只读主/子Agent禁止生成/回填/预览写出，只开放列入白名单的读取核验动作。源模板、输出和侧车状态分别检查目录权限。新Python工作流作为资源包含在构建中，后续更新包必须同时带workflows/*.py与config.properties默认资源；旧外部配置不覆盖，新键靠内置默认值补齐。

测试环境使用现代Windows/Python做合成数据验证；不等于已在内网Win7/Python3.7及所有实际资料完成验收。
