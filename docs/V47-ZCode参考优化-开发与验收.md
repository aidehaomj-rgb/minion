# V47 开发版：任务运行、上下文与工具效率优化

后续交付：已按用户新请求制作 [V47小更新包](releases/V47-任务运行与上下文优化小更新.md)，支持V40–V46。下文“不制作更新包”为此前开发阶段记录；应用源码未因打包而改变。

本轮延续 ZCode 源码审计后的开发，不制作内网更新包、不推送 GitHub，也不修改用户正在运行的安装目录。源码参考固定为 `zai-org/ZCode@a9fe401eede6e6e5e01be9048679c206fe6f02d9`，具体参考依据见 [源码审计](2026-11-05-zcode-source-audit.md)。仅迁移设计，未引入其 Node/Electron 运行环境。

## 1. 本轮实现

### P0-A：外部作业账本与事件等待

- 新增会话级 `RuntimeJobRegistry`，保存 jobId、taskId、指令修订、attempt、owner epoch、外部标识、状态、结果路径和取消请求。数据位于项目 `.minion/runtime-jobs/<sessionId>.json`。
- `Process.start` 可选择 `waitForCompletion=true`，用于需要等完再继续的一次性作业；常驻服务默认不阻塞主任务。完成回调在输出日志归档之后发布。
- 现有 MySQL/PostgreSQL/Oracle JDBC 工具增加 `submit/status/wait/cancel`。`submit` 先登记再连接，立即返回 jobId；主循环等待完成事件，读取结果后再执行当前步骤，不自动重复提交 SQL。
- JDBC 后台线程 2 个、排队上限 8；数据源设置可配置 `queryTimeoutSeconds`，默认 300、最多 86400 秒，模型参数不能提高用户设定。提交时冻结数据源配置。
- 异步结果写入授权临时目录后才发布成功。同步 query/schema/describe 保持兼容，等待时显示外部作业状态，并支持尽力而为的非阻塞 Statement.cancel。
- 新用户要求、会话切换和取消具有任务/修订隔离。旧作业结果可保留供核对，但不驱动新任务。进程退出成功只是工具证据，不等于业务验收完成。
- 重启后的未决外部作业标记 `unknown`，暂停等待核对，不凭 PID 重连、不自动重提。取消请求不冒充服务端物理停止证明。

**边界**：本轮统一账本已接入进程和已有 JDBC 工具。浏览器下载、子 Agent 协调仍使用原有专项控制器，并未全部迁入新账本。尚未实现 MaxCompute 专用驱动、鉴权和实例恢复适配，也未连接真实内网数据库验证。

### P0-B：可配置的有界长任务续接

- 修复热去重记录超过 512 条后无法继续识别进展的问题。热索引保持有界，历史签名按任务分片落盘至 `.minion/progress/<sessionId>/<taskId>/`；旧签名淘汰出内存后仍不能冒充新进展。
- 桌面会话通过配置使用 `agent.task.continuationWindows=96` 和 `agent.task.tokenBudget=10000000`。窗口是轮数耗尽后的续接，不等于一次模型调用。未显式配置的旧调用入口保留 24 窗口行为。
- 无有效进展不能无限续跑；纯状态查询不增加业务进展。外部事件等待不发模型请求，也不消耗无进展续接窗口。
- 续接预算与完成校验共用进展规则：Process/JDBC 状态等待、日志查询、权限审计及浏览器状态等待不计分；Diagnostics 的时间/自动导出名、Build 的 UUID/耗时等元数据变化不算新事实。真实查询数据、文件内容和浏览器动作回执仍可计分，原始输出不删改。
- 总 token 预算达到上限时以 `task_budget` 暂停，不能显示任务完成。预算按实际返回的 usage 统计，不声称网关缺失的 token 也能准确计量。
- 进展账本损坏或不可写时明确告警，不通过清空历史或自动授予预算掩盖问题。

### P0-C：类型化来源、当前工作集与技能退场

- 消息增加可空来源类型：real_user、task_control、compact_summary、tool_evidence、skill、history_recall。合成控制提示、记忆和工具内容不能取得真实用户授权。
- 新字段保持旧事件序列化兼容；不为旧记录强行补默认值，避免破坏不可变事件摘要链。未知的显式类型不降级为真实用户输入。
- 当前工作集单独保留任务/修订、最新真实用户事件 ID、最新要求、当前步骤、未完成项、下一步、当前修订产物引用；旧修订完成回执不能成为新要求的完成证据。
- 自动压缩后只按当前工作集恢复最多 2 个最近观察过、已授权的小文本文件，每个最多 2400 字符，源文件最多 512 KiB。不扫描项目，不完整重读历史指令。
- 文件片段附原观察哈希与当前哈希；文件变化明确标记 `changed_since_receipt`，当前磁盘内容不冒充原始 Read 快照。
- 未解决的工具失败不按普通成功结果随意去重/截断。技能正文限定最多 2 项、24000 字符、8 个用户回合或 30 分钟；压缩不刷新租期。过期保留有界来源引用，需要时重新加载。
- **完整自动摘要目标仍为 150000 token**。本轮未将其改回 80K/120K；请求投影、工具去重与完整摘要不是同一操作。服务端确实拒绝上下文时仍保留已有应急处理，不伪称服务容量无限。

### P1-D/E/F：按能力调度、资源锁和稳定前缀

- 不按模型名称推断能力。当前模型有有效单调用证据后，可在真实任务中试行最多 2 个独立只读调用，首次仍串行验证；完整成功后才启用经观察证实的有界只读并行，最多 4 个。
- 写入、未知副作用、确认和依赖动作是调度屏障。批次中断先取消所有结果 Future，再中断工作线程；迟到成功不能重新启动后续写入。
- Write 首次保持 1000 字符保守分块，实际成功后可随输出预算渐进增长，保留 JSON 余量；协议截断/错误、模型切换、能力过期时退回保守模式。
- 已知 Excel/文档输入输出按规范路径资源锁保护，独立文件可以并行；同文件仍互斥。Process 等待、JDBC 网络等待不占无关文件写锁。范围不可证明的 Shell 仍保守独占，共享浏览器仍有互斥锁。
- 稳定 system 规则与动态任务控制分离；技能/已发现工具采用受控动态信息。不添加假定网关支持的厂商缓存字段，也不宣称实际命中缓存或固定提速比例。

### P1-G/H：中文召回与可观察性

- 从当前完整要求、最新纠正、活动步骤生成多个有界短查询，保留长要求末尾关键限制；融合后按 task/revision/来源过滤。历史查询最多 3 次，注入片段仍有界。
- 同一轮召回中，同一规范路径来源只校验一次文件指纹；下一轮重新验证，同大小同时间戳改内容仍可失效。未加入向量库、额外 embedding 服务或模型重排请求。
- 记录 MODEL_REQUEST、FIRST_DELTA、LOCK_WAIT、EXTERNAL_WAIT，并沿用检索、压缩、工具和验收阶段计时。未观测阶段标为 unknown（elapsedMs=-1），不是假定耗时为零。各阶段可重叠，不能简单相加当总时长。
- 工具派发时固定 session/task/revision/generation 归属。用户停止或补充新要求后，旧线程即使忽略中断并返回成功，也只能记入原任务运行记录，不给当前任务加进展或验收证据。

## 2. 核心回归场景

| 场景 | 自动化验证重点 |
| --- | --- |
| 超过 512 个不同工具回执、重新加载去重账本 | 新进展不冻结、旧回执不重新计分、损坏记录不放行 |
| 连续 compact、用户修订要求、旧任务 nextStep | 当前要求优先，旧步骤不复活；原始事件保留 |
| 压缩后文件被外部修改 | 当前/历史哈希分离，有界片段带版本标记 |
| 技能过期与重新加载 | 正文退场、来源保留，压缩不能延长租期 |
| 真实本地 Java 子进程完成 | 仅提交一次、日志落盘后通知、完成前不再请求模型 |
| AgentLoop + JDBC 驱动替身慢查询 | 实际 JDBC 控制链、先登记后执行、结果落盘、无轮询重提 |
| JDBC 排队/期限/取消/忽略取消 | 有界线程队列、unknown 不当成功、迟到结果不恢复旧任务 |
| 旧工具忽略中断，用户已开始新任务 | 原任务结果不能记入新任务 evidence/progress |
| 只读批次中断、写屏障、同路径冲突 | 未执行后续动作不得启动；独立资源不无谓互阻 |
| 长中文要求尾部限制、同秒同长度来源变更 | 多查询覆盖与来源正确失效、跨项目隔离 |
| 旧消息/预算 JSON 与事件记录 | 新可空字段不破坏旧摘要链，合成消息不能授权全局记忆 |

以上是开发机离线自动化/替身验证，并非已经在用户 Win7、真实 DeepSeek/Qwen 或 MaxCompute 上通过实机验收。完整回归结果见 [验收结果](V47-开发验收结果.md)，逐套件计数、构建产物和源码指纹见 [验收 JSON](V47-开发验收结果.json)。

## 3. 使用与后续边界

- 数据库：在原有“设置 → 工具 → 数据源”配置连接和查询超时。需要等较久的只读 SQL 使用现有数据库工具的 `{"action":"submit","sql":"SELECT ..."}`；返回 jobId 后由宿主等待事件，模型无需定时发 status。`query` 仍可用于原有短查询。
- 进程：一次性脚本/构建若要等结束再做下一步，使用 Process 的 `start` 并指定 `waitForCompletion=true`；需要长驻的网页服务不要指定该项。等待成功后仍须验证输出文件或业务结果。
- 出现 `unknown` 时先根据 jobId、归档路径和原服务状态核对，不直接再次 submit/start；明确用户停止后也不会自行复活任务。此限制是防重复副作用，不是把 unknown 当完成。
- 界面“关于”显示 **V47开发版（任务运行与上下文优化）**，不表示内网已更新。
- 此轮不修改旧交付压缩包、桌面快捷方式、模型设置或用户数据库配置。
- 源码和离线自动化验收完成后，仍需真实内网回放：长中文任务、150K 后压缩续接、用户修订、慢查询、取消与模型断流。需记录首 token、模型调用数、token、锁等待和错误率；未测量前不给性能百分比。
- MaxCompute、浏览器/子 Agent 的统一作业适配、真实 38 分块和 1M 上下文质量评测是后续独立验收项，不能把“有基础设施”等同于这些适配均已完成。
