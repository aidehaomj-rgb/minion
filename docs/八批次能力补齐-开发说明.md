## 本次可用的接线

1. **当前任务控制**：AgentControl的plan_steps/step_change登记修订、依赖、范围、验收和实际工具回执。压缩优先交接运行/未完成步骤，38项清单也不让已完成项挤掉最后的活动步骤。完整原文仍在会话/事件记录，不重复复制到每一次步骤变更。
2. **持续执行**：原有3次自动窗口之外，有新且去重的实际进展才可继续，总共最多24次；重复Read、状态查询、换UUID的相同测试报告不刷新进展。等待用户/重试/预算暂停/中断/阻碍与完成分开，不能用无限重试假装稳定。
3. **真实验证**：Build发现实际Python/Maven/Gradle/npm测试，保留计数、退出码、源码和日志摘要、范围及报告路径。syntax_check、零测试、未知测试数、普通命令退出0不是测试通过。源码/日志被改后旧报告失效。Python 3.7的unittest参数差异、同秒同长度改代码的pyc缓存已处理。
4. **记忆检索**：记忆可替代/冲突/带适用条件；引用文件改变后不继续以已核验事实注入。中文BM25/别名/文件和任务过滤、按需索引，不启动扫描全部历史，不默认共享其他项目私聊。全局身份偏好仍由用户控制。
5. **模型与性能**：显式合成能力探测、绑定配置指纹及失效入口；显示usage来源和可观测耗时。工具schema按任务加载，DiscoverTools可发现已启用工具但不扩权。完整请求总量与服务端总usage对应校准，schema是固定加项，不能拿工具定义开销放大每一个历史字符。默认压缩线仍是150000 token；真实服务端超限学习是另一条明确的限制。
6. **多Agent**：结构化task已接入真实AgentLoop/SubAgentLoop，不再只是独立调度器类。独立连接继承主模型、有界队列默认并发2、范围唯一、依赖在主Agent核对后释放，取消/超时传播，旧物理执行未退出不释放写租约。等待子结果时主Agent休眠，不用模型反复查询。旧同步task仍兼容。
7. **浏览器与成果**：BrowserAction现在实际注册在浏览器插件内，仍受启用开关控制。动作等待、iframe、页面版本、人工接管、下载/分页证据；ArtifactVerification区分文件/图像/PE头元数据、实际HTTP和启用的浏览器检查。文件存在/结构检查不等于业务正确、视觉合格或程序已运行。
8. **回放与兼容**：人工金标准指标和Python 3.7离线汇总器；没有标签的指标保持unknown。首次原生调用处理含`!`安装路径的JNA DLL加载。中文/空格路径下被引号包裹的exe命令补齐cmd `/s /c`外层引号，Build/Process不再把exe路径和参数拼成一个“命令名”。

## 结构化子任务示例（模型工具协议）

先查询AgentControl status取得当前revision。代码修改任务可以这样登记：

```json
{
  "description": "只修改src/module_a下的模块，给出变更和实际证据路径",
  "revision": 1,
  "stepId": "module_a",
  "scope": ["src/module_a"],
  "dependsOn": [],
  "acceptance": "接口与指定测试预期一致；列出未验证内容",
  "mode": "worker",
  "requiresMerge": true
}
```

- 登记结果是queued，不是完成；AgentControl child_status分页显示真实状态、attempt、执行根、结果与证据。
- 当前模型工具入口逐项登记，dependsOn应引用已经成功登记的stepId；有依赖的下游应等上游登记回执后再派发。独立分块可同轮并行派发；协调器的乱序原子批量API已有测试，但不能把该基础API冒充模型入口已支持任意乱序登记。
- 代码隔离使用已有Git worktree，要求登记scope没有用户未提交/未跟踪修改。其他脏范围不动，不执行commit/reset/clean，不强制清理脏worktree。
- 非Git/办公任务可用isolatedOutput=true创建独立输出目录。scope相对于执行根；不同分块写不同产物，不能让多个worker覆盖同一个Excel文件；最后由父任务汇总。
- 范围worker仅放行内置、能核对目标路径的Write/Edit/Document/Excel/Artwork动作；不能据此放行任意Shell/Python/插件。需要的测试/构建由主Agent实际运行。这是应用层边界，不是操作系统沙箱。
- 先实际Read子结果证据，再用child_review(stepId,attempt,receiptIds,note)核对；状态查询、子Agent自己的回执或一段“完成”描述不能释放依赖。
- 独立输出按现有合并预览/检查点流程应用；代码worktree还核对派发时主目录基线。合并不是完成，必须实际Build验证并validate_merge，再child_status同步联合验收。
- child_cancel/child_reject需原因；child_retry需当前attempt、核对依据及sideEffectsChecked=true。旧尝试/隔离目录保留审计，不洗掉旧记录。新尝试不会被旧失败子记录永久卡住。
- 最新要求修订或主模型切换会停止旧分工。恢复协调记录不自动重放：child_resume_queue只解除队列恢复等待，运行状态不明的项仍是interrupted_needs_review，必须另行实际核对。
