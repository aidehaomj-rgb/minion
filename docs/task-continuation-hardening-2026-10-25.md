# Minion 长任务续接与防误结束（源码阶段，未打更新包）

## 参考边界

- [Codex Goals 官方说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)：任务目标持久化、按证据完成；空闲续接需要有效目标、预算和安全边界。预算耗尽不是完成。
- [Claude Code 工作原理](https://code.claude.com/docs/en/how-claude-code-works)、[Stop hooks](https://code.claude.com/docs/en/hooks)：收集上下文—行动—验证循环；Stop 可阻止提早结束，但必须有连续续接上限，避免自旋。
- [CodeBuddy Code 最佳实践](https://www.workbuddy.cn/docs/cli/best-practices)：自动压缩保留文件状态与关键决策，长任务可从持久会话继续。公开资料并不保证任何产品永不误停。

这些是可借鉴的**控制机制**，并不意味着 Minion 可以用 Qwen3.8-27B 完全复刻专有模型或产品内部实现。

## 本轮落实

1. 工具轮数边界不再被当作任务结束。普通会话在有工具调用、无新用户排队/补充、非计划任务、未中断时，最多自动续接 3 个新轮段；每段仍遵守既有工具权限、确认和幂等保护。无工具动作不续接，防止只说“继续”的死循环。
2. 自动续接不向持久会话伪造 `USER` 消息，也不创建新任务 ID；仅在下一次模型请求中注入临时的内部续接提示。用户主动“继续”会重开本次安全续接预算。
3. `TaskState` 持久化 `pauseCode` 和自动续接次数。预算尽时显示**暂停且未完成**，不会推进后续队列；重启后不会擅自恢复写入类任务。
4. 主要失败入口标记机器可读原因：`round_limit`、`no_progress`、`waiting_user`、`review_unknown`、`model_silent`、`output_length`、`malformed_tool`、`stream_incomplete`、`repetition`、`model_error`、`interrupted` 等；`/task` 可查看。
5. “把这个问题解决完/修好/改好”等操作型指令纳入确定性最低证据门槛；只读取源码或模型说“解决了”不能批准写入型任务完成。“如何解决”“给我解决方案”仍允许纯回答。
6. 侧栏和页签不再把所有“停止运行”显示成绿色完成点：真正完成是绿色，暂停/失败是橙色，运行中仍为黄色呼吸点；任务详情显示暂停代码与原因。
7. 跨轮工具收据持久化执行时判定的“只读/写入”标记；旧版没有标记的历史收据不能反推写入。数据库查询、SQLite schema、Python status、构建产物列表、Git diff 等只读结果不能冒充写入证据。Excel/Document/Database 的成功输出文件也记录当前文件哈希并在拟完成时复核。
8. 核验器说 `waiting_user` 不再足以停机：候选回复必须**实际提出可回答的具体问题/请求**，或者存在明确的权限阻断；“下一步需要向用户提问”只是计划，会继续要求模型调用 `AskUserQuestion` 或当轮直接发问。正确发问后等待用户是正常暂停，不能在没有用户输入时擅自继续。
9. 显式“最开始说的要求”等回指和未完成任务中的“还有就是…”补充不再误开新任务；原始目标持久保存，超过 12000 字的中段会按当前关键词选取来源片段注入，必要时可用 `Memory(action=read_task,offset=…,limit=…)` 分页读当前任务完整原文。历史归档按每条消息记录任务 ID，跨任务压缩时不再把旧任务消息全部误归到当前任务；旧无 ID 归档仅能保守回退。
10. 标称 1M 窗口的会话默认在约 **120K 估算输入 token** 自动压缩；现在可在模型设置中逐模型配置“稳定工作区”（0 为默认 120K），设置预览/进度提示按实际阈值显示，主会话与子 Agent 均使用各自模型的工作区。具体模型窗口仍保持原配置；超限/空响应的会话级降载仍优先。摘要批次预先分段至约 32K token，近期链太大时再试更小的恢复保留窗口。首输出超时且输入已达 64K 会优先尝试一次安全压缩，不必先等长时间网络重试。原文归档或结构校验失败时不替换旧上下文。
11. 新增不含提示词或 API Key 的 `model-health` 诊断条目：模型、任务 ID、请求估算/实际输入 token、输出 token、首个输出延迟、请求总耗时、finish reason、工具调用数、异常类型。可以在内网用真实会话区分“1M 可接收”和“长任务可稳定执行”。

## 验收与尚未解决的边界

- Java 8 离线定向回归覆盖续接、等待用户、原始目标回指、跨任务历史隔离、200K 历史预分段压缩等；最终总数以完整定向复跑报告为准。测试临时目录放在工作区；默认沙箱临时目录不允许原子重命名，直接用它会产生环境性失败。
- 尚未在用户内网 Win7 + Qwen3.8-27B 的真实误停会话上回放。模型兼容 API 的空响应、错误 `finish_reason`、不稳定工具调用及语义核验误判不能靠本地模拟保证彻底消失。
- 当前自动续接仅覆盖**安全的工具轮数边界**，不跨越用户拒绝、未知写入副作用、核验不明、连续无进展、网络/模型错误；这些必须暂停并显示原因，不应无人值守反复执行。120K 是保守默认值而非实际服务端精确容量；提高逐模型稳定工作区之前，先在该内网模型上做长任务回放。复杂任务的语义正确性仍以用户登记的验收规则、实际测试和产物复核为准。
- 本轮未制作更新包，内网 V37 暂时没有这些改动。更新前还需用内网真实失败日志回放，至少记录：任务 ID、`pauseCode`、模型 `finish_reason`、压缩前后 token、工具收据、StopGate 判定、队列/补充状态，并核对真实文件副作用。
