# Minion 长对话记忆（离线版）

本功能将四种信息分开：当前任务状态、模型可见的压缩摘要、压缩前的原始消息、跨会话的项目记忆。优先级始终是最新用户要求 > 当前任务状态 > 项目记忆/历史资料 > 旧摘要。检索命中不会自动成为待执行指令。

## 逐条事件与异常退出恢复

- 用户消息、助手回复（含思考和工具调用）、工具结果、技能注入、补充消息、工具图片上下文在加入工作消息列表**之前**写入 `.events/<session-id>/` 的独立事件文件。事件含顺序号、事件 ID、时间、任务 ID、关联文件路径和 SHA-256 校验；用户消息还带当前任务控制状态。会话 JSON 保存已包含的事件序号，重启时只重放其后的事件。直接由 GUI 导入/保存的消息也由保存入口补记。
- 压缩时先按下节保存原文，再写入新工作上下文的过渡事件，最后替换内存消息列表；因此崩溃发生在过渡事件与会话 JSON 更新之间时，仍可恢复压缩后的上下文，不会让被压缩的旧消息重新冒出来。事件校验失败或序号缺失时拒绝加载，而不是静默拼接不可信历史。删除会话也删除事件目录。
- 这保障单进程异常退出后的消息重放；尚未提供跨进程并发写入、操作系统级 WORM/断电持久化承诺。工具的外部副作用本身不由消息日志回滚或自动重试，恢复后仍需根据工具回执核对。事件文件可能包含完整附件/工具输出，需按敏感数据保护。内网 Win7 真机的强制结束进程回放仍待执行。

## 压缩与追溯

- 自动压缩、手动 `/compact`、服务端超限恢复及长上下文空转恢复走同一归档入口。压缩替换模型上下文前，整个原始消息流（含保留区、工具结果及子 Agent 返回的工具消息）写入会话目录 `.history/<session-id>/`；稳定事件 ID 避免多次压缩重复归档。旧会话在首次归档时补 ID。
- 每段原文使用追加式独立文件，附事件 ID、任务 ID、时间、SHA-256 校验及可识别的工具文件路径；检索读取 `.idx.json`，原文分页按消息 ID 读取。模型生成的旧摘要只保留谱系，不作为事实证据。追加式不等于操作系统级 WORM，拥有目录写权限的人仍可能篡改；读取时校验哈希。
- 归档失败时本次压缩不替换历史。摘要必须按指定顺序填全八个字段；字段空缺/错序则原历史不替换。最新用户原话若被紧急压缩吞入摘要，会原样保留为独立用户消息；当前任务/补充锚点仍需通过检查。
- `Memory(action="search_history", query="关键词", path="可选文件名")` 返回消息 ID、事件 ID、时间、任务、路径、匹配偏移及来源文件状态；`Memory(action="read_history", id="消息ID", offset="匹配偏移", limit="12000")` 分页读取。文件变化/消失时标记 `changed`，原文仍可追溯但旧结论不得当当前事实；没有可核验文件元数据则标记 `unverified`。删除会话时同步删除其归档。
- 只对升级后发生的压缩生效。升级前已被旧版本压缩丢失的原文无法自动恢复。

## 项目记忆

- `Memory(action="remember", type="feedback", content="...", source="用户明确要求")` 写入分类记忆；类型为 `user`、`feedback`、`project`、`decision`、`reference`。新条目默认**待核验**，工具写入批准不等于事实核验。
- `Memory(action="index")` 只列已核验的短索引；`list` 查看所有条目及状态/项目/来源/更新时间；`verify`/`unverify` 改状态；`edit` 修改后重新待核验；`forget` 移入项目 `.minion/memory/trash`。仅已核验条目参与自动检索注入。手工编辑 Markdown 正文后自动降为待核验。
- 分类记忆保存在项目 `.minion/memory/entries/*.md`，正文可直接查看/编辑，顶部注释保存类型、来源、适用项目、更新时间与核验状态；旧版 `.json` 条目仍可读取。原有 `project.md`、`handoff.md` 及其工具动作保持兼容。不同项目的私人记忆和历史不会互查；共享 Markdown 知识库仍由 `Knowledge` 工具管理。
- 当前版本自动提取关闭，不把一次性任务结论写成永久事实。向量检索仍未启用。
- 子 Agent 禁止直接写项目记忆、只能读取共享知识库；其工作消息留在独立记录，压缩前也归档原始事件。主 Agent 接收限定长度的分项结果、证据文件路径和完整记录路径；子 Agent 的自报结果仍须主 Agent 核对。

## 请求前按需找回

请求投影只用于模型输入，不修改原始会话：当前工具输出上限约 12K 字符，旧工具输出约 4K，旧思考/助手正文/工具参数进一步收紧。已消费的 `AgentControl`、`TodoWrite`、`DiscoverTools`、`Context`、`Skill` 控制调用及成对结果从模型历史中剔除，任务目标、清单和证据仍由当前任务控制面保留；真实文件、命令、数据库和文档工具结果继续可见。交互界面也隐藏这些内部登记，但事件日志和任务面板保留完整记录。

新一轮请求时，Minion 从当前项目分类记忆中选少量相关条目；同一任务恢复时，还会在该会话已归档的原文中选少量命中片段。**执行中压缩本身不再触发历史检索或完整重读。** 压缩后主/子 Agent 直接接收当前任务、最新修改、清单、处理范围和最近工具回执的一次性临时交接，在原回合继续执行。只有用户明确追问历史，或当前步骤确实缺少具体证据时，才定向读取原文。明确追问历史时可跨当前会话的任务段检索；具体问题没有命中时不回退召回不相关决定，只有“之前怎么定的”这类泛问保留有界决策检索。

摘要携带任务 ID / 指令修订号。其他任务或旧修订摘要只提供事实、决定、证据及不确定性，不向模型传递旧目标、旧待办和旧下一步。当前摘要的最新要求字段由控制面绑定，不能由摘要模型任意改写；收到新的用户补充后，旧“下一步”失效但文件及已处理范围证据仍保留。系统修复 USER 消息不当作真正用户要求。历史思考保存在原文，但不再作为摘要证据输入。新增元数据可空，兼容旧事件和原文校验。

检索片段附来源 ID，作为临时参考放入模型请求，不写入会话，也不覆盖用户的最新消息。没有命中时不增加上下文。压缩交接同样不落成新用户指令；压缩阈值仍为 150000 token。

检索使用本地文字索引和中文相邻字匹配，无联网或向量数据库依赖。历史归档可能包含原始工具输出与图片数据，应与会话文件一起按敏感资料保护和备份。当前单条消息检索索引最多 200 万字符；超出部分仍保存在原文中，但关键词可能无法命中，可通过已知消息 ID 分页核对。真实 Win7/内网 Qwen 的耗时与 token 增量仍需试机回放。

## 回放验收

自动化回放覆盖：超过 20 万 token 后修改任务要求（`AgentLoopCompactTest.changedInstructionAfterTwoHundredKTokensSurvivesCompaction`）；重复压缩与 38 个子 Agent 分块不重复归档、可找回原文（`HistoryArchiveTest`）；模型切换后的会话重载仍能按事件 ID 找回证据；文件更新前后均会使旧结论标记 `changed`；跨项目记忆隔离及手改 Markdown 后取消核验（`ProjectMemoryStoreTest`）。结构化摘要缺字段时禁止替换原文，紧急压缩保留最新用户原话，泛问“之前怎么定的”会回退找决策证据（`AgentLoopCompactTest`）。

在内网 Win7/Qwen 上还需手动回放同类真实任务：记录“最新指令是否被遵守、原文定位是否准确、已完成步骤是否重做、是否跨项目泄漏”，并从 `DiagnosticLog` 中统计检索耗时和注入 token；未试机前不能将本地模拟测试当作内网验收通过。

2026-10-25 本机使用 Zulu JDK 8 + Maven 离线编译并通过事件/存储/压缩定向测试 116 项（其中 `AgentLoopTest` 89 项）；历史记忆定向回放亦已通过。全量测试中的本地 HTTP/MCP 用例受当前沙箱 `Permission denied: connect` 限制，不能据此判定内网环境的网络功能通过或失败；真实 Win7/Qwen 回放仍待执行。本轮未制作更新包。
