# 任务作用域压缩与续接（V44 开发）

用户已要求直接完善现有上下文/压缩实现。本轮在 V43 源码上开发，不制作或覆盖已交付更新包。

## 问题与实现

- 八字段摘要原先只验证格式，模型仍可把旧要求写进“最新用户要求”。该字段改为由当前控制记录确定性绑定，摘要不得自行选择当前目标。
- 摘要增加本地任务 ID / 指令修订号。请求和下一次合并前，其他任务或过期修订的摘要仅提取事实、决定、证据及不确定性，不携带旧目标、待办、下一步及重复任务快照。无作用域旧摘要只在任务原文匹配时作为当前背景。
- 保留区仍含较早任务的用户/助手正文时，模型副本标为历史引用而非重新下发的指令；同任务早期用户原话标明修订与冲突优先级。消息原文和工具配对不改。
- 摘要批次标记消息事件及任务来源；已知其他任务原文不参与当前待办推导。原始消息仍先归档，失败仍不替换。
- 用户补充增加指令修订号，旧断点保留文件/处理范围证据，但过期“下一步”不再引导续接。压缩后最近原话必须是真用户输入，不能误选系统修复消息。
- 自动取回默认当前任务；新任务即使刚发生压缩也不打开旧任务检索。补充即时刷新检索词；只有明确追问历史才跨本会话的任务段，未命中不随意召回别的决定。
- 执行中压缩不再单独触发历史检索。首个后续请求尾部加入一次临时交接：当前任务/指令修订、最新要求、处理范围、当前未失效的下一步、主清单及最近三条工具回执；主循环直接在原回合继续，不插入新的人类消息，不完整重读旧对话。子 Agent 同样使用自己的分工/清单/回执续接。
- 还原的用户原话放在近期工具回执之前，防止看起来像工具结束后又要求从头重做。历史思考仍在原始记录中，但不送入摘要模型，不把猜想和废弃计划提升为事实。
- 新增序列化字段使用可空类型，旧版本缺字段时不补出默认值，避免改变不可变历史事件的校验哈希。旧版已有补充但无修订号的任务，过期下一步默认不再可信。
- 区分“继续当前任务”与“继续做新任务/换项目”；保留普通续接及用户纠正行为。

## 边界及测试

Java 8 / Win7、现有模型协议、150000 token 阈值、原始会话事件/项目记忆隔离不变；不新增服务、向量库或依赖，也不为压缩增加额外模型审核调用。

回放覆盖：旧任务未完成摘要后切换任务、同任务改要求后反复压缩、系统修复 USER 不变成最新指令、补充后过期断点、压缩后的检索作用域、重启与模型切换、20 万 token 历史以及主/子 Agent 工具配对。模拟模型通过不代表内网模型绝不会偏题，仍需真机回放。
