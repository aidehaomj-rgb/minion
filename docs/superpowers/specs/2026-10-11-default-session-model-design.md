# 会话默认模型选择（用户已确认）

## 需求与现状

用户要求增加每次会话打开时的默认模型选择。现有设置页“激活”会传播全局模型变化，输入框模型选择仅影响当前会话；不能把新默认选择实现为全局激活，造成旧会话模型被意外更换。

## 建议行为

- 设置→模型增加明确的“新会话默认模型”下拉框，从已配置模型中选择；旁边说明仅用于新建会话。
- model.json新增defaultModelName，旧配置迁移沿用当前激活模型；重启保留选择。模型删除后默认回退到仍存在的模型，至少保留一个。
- 新建会话使用默认模型，并保存独立模型选择；重新打开已有会话继续使用该会话保存的模型，缺失或已删除时提示并回退。修改默认值不改变已打开/运行中会话，不中断任务。
- 输入框现有模型按钮继续只影响当前会话，切换项目不改变默认模型。

## 验证与交付

覆盖旧配置迁移、持久化、删除回退、两会话隔离、新建与旧会话恢复，以及设置页控件检查。与刚完成的流式循环修复共存。本请求未要求打包。

如用户的“每次会话打开”是指强制覆盖旧会话的模型，需要另行确认；默认不覆盖用户先前的会话选择。
