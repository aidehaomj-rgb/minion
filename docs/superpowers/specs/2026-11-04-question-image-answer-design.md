# 提问回答支持图片：设计与验收

## 范围与约束

用户要求规划补齐 Agent 短板，并修复提问阶段不能附图片。本批先修复明确的交互缺陷，不顺带重写执行引擎，不制作更新包。Java 8 / JavaFX 8、Win7、现有离线依赖不变；150K 自动压缩默认值和主/子同模型规则不变。

## 已确认原因

- `InputView.onAction()` 的 ANSWER 分支主动拒绝所有图片；纯图片回答也会被空文本判定拦截。
- `SessionManager.sendAnswer` → `AgentLoop.answerAskUser` → `AskUserQuestionTool.complete` 仅传字符串。
- 普通输入已有上传/剪贴板图片路径，工具返回图片已有“先完整 tool 结果、后图片 user content”的兼容协议；应复用而不是在 TOOL content 内塞不兼容的图片数组。

## 设计

1. 回答使用不可变的文字和图片快照，保留旧的纯文字入口。仅图片也算有效回答；空回答、附件无效、已取消或重复回答返回 false。
2. 工具输出保留现有纯文字/编号选择的格式。带图时输出结构化回答、原问题、附件名称/类型；原始 base64 不写进工具正文。数字选择加图片不能丢选项含义。
3. 图片随 ToolResult 交给现有工具图片传输链路，放在本轮所有 TOOL 回执之后。并行重复提问共享一个回答，图片只由等待槽的拥有者返回一次。
4. 新图片消息带可空的 `replyToToolCallId` 本地标记及 `toolImage=true`，明确属于当前提问资料而非新任务。旧消息该字段为 null，不改变旧不可变事件的序列化哈希。请求投影复制此标记，不输出到模型 API。
5. 运行和历史回放均只显示一次回答，含图片名称；隐藏重复的协议承载消息。图片像素仍留在持久化历史并随下一请求发送。
6. 每次实际挂起有短期提问 ID。输入框携带显示时捕获的 ID 提交，旧提问草稿不能被下一提问接收。仅在回答成功接收后清空；状态变化/取消/重复提交时保留草稿和附件，不悄悄创建新任务。
7. 无独立视觉模型切换或外网服务。纯文本模型拒绝图片时沿用已有明确错误提示，不把“发送成功”解释为“识图成功”。不自动重放有副作用的工具。

## 验收

- 文字＋图片、仅图片、编号选择＋图片、多个图片均可提交；原有纯文字测试不变。
- 图片快照不被调用方后续修改；过多/空/明显无效附件不唤醒等待；取消和重复提交不能污染下一提问。
- Agent 下一请求中的 assistant/tool 完整配对，图片在全部 TOOL 结果之后；图片不是最新用户任务，任务 ID/修订不因回答附件而重建。
- 会话保存/重载后像素仍可用；回放回答仅出现一次且无 base64 泄漏到聊天正文。
- GUI 实际发送路径使用新接口，接收失败不清草稿；Enter/Shift+Enter 既有规则不变。
- Java 8 编译、定向测试、全量回归。真实内网模型和 Win7 交互另列待验收，不冒充已验证。
