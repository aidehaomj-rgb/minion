# 任务执行与验证闭环：继续八批次开发

用户已要求继续实施2026-11-04的八批次计划。本轮按依赖推进，不覆盖旧V44安装包，也不改变主子同模型、150K默认压缩、Java8/Python3.7兼容等既有约束。

## 先解决的执行根因

- 原有任务控制能保存目标/修订/断点，但没有带依赖与验证条件的独立步骤。新增可空的任务工作流；旧会话缺字段保持兼容，不修改原始事件。
- 原有自动续接只看总次数3次。改成无新证据仍最多3个续接窗口，有新且去重后的实际工具回执可继续，但总窗口仍有限；Todo、状态查询、模型自述不算进展。用户恢复重开预算。中断/等待用户/未知副作用不自动续接。
- 步骤结束需引用本任务真实成功工具证据；文件验收匹配内容哈希。完成语义仍需独立StopGate复核，回执成功不等于业务正确。
- 新用户修订使旧步骤执行计划失效；显式重新绑定新修订后才能执行。已完成事实保留，取消/替代有来源和记录，不允许工具改写用户原始要求。
- 工作流进入控制面、压缩交接、结束核验和完成阻断；不能仅做一个无人调用的新类。

## 测试验证

- Python测试不能继续用compileall冒充。发现实际测试配置，选择已存在的项目命令/pytest/unittest；没有测试明确not_configured。语法检查独立syntax_check。
- 构建结果包含执行类型、状态、退出码、超时、耗时、日志和版本证据；保存本地日志，测试结果不能当作未运行的质量承诺。超时/取消收口进程树。
- 验证覆盖循环、步骤依赖与取消、修订后的旧步骤、文件变化、错误断言、零测试、缺工具链、协议/压缩/恢复；本机模拟与内网实测分开记录。

## 后续批次接口

工作流提供独立步骤ID、依赖、范围、验收与证据，供多Agent绑定与联合验收。真实测试结构化输出供结束核验消费。记忆继续采用本地Markdown与关键词检索，优先补充已核验决定的替代关系与来源失效，不盲目引入向量服务。

## 发布与边界

无新网络探测或启动全量扫描，无新增运行时依赖，不删除用户项目/配置/会话。实际Win7/内网模型仍需用户环境回放。仅对代码和证据确实完成的任务勾选，不把八个批次的全部规划宣称为已经实现。
