# 任务清单当前化投影与任务条/面板美化（I 批）设计

日期：2026-11-25（HEAD 3347b24，2.4.8 打包后）
状态：**方案已获用户确认（AskUserQuestion：已完成项保留当前任务已完成步骤；面板保留全量+美化）**。
症状来源：用户实机截图——任务条 20 行里 18 行是历史修订的已结束子agent（chunk_1…returned_needs_review），
当前 2 条待办被挤到最底；计数 n/m 把历史算进去失真；样式为纯 Label 单色，不够主流 agent 观感。
用户指令："参考主流agent，把当前最新的任务情况列出来，之前已经完成的就不用了；执行过程中有新引导进来，
执行过程中增加任务清单就好了；任务清单 UI 做好看一些，包括点开任务栏也美化。"

## 1. 根因（HEAD 实测）

- `TaskBoardModel.snapshot`（TaskBoardModel.java:61）**直读 state.children 全集**——不经修订过滤，
  历史修订的已结束子agent全部入行；TaskStrip 与面板 board 段共用该快照。
- 计数/当前行/徽标都基于全量行 → n/m 失真、currentTitle 可能落在历史行。
- 顺序为 todos→children→background（HEAD），但历史 child 行数量压倒当前待办；旧包顺序更糟（child 在前）。
- 样式：workbench.css:572-586 仅单色 Label + 顶边框，无卡片/进度/状态徽标/行 hover 底色。
- 实时性本身没坏：1s 轮询 + signature 重绘；新引导推进修订后**旧历史行不会自动消失**（投影全量）才是观感根因。

## 2. I1 当前化投影（additive，新方法；旧 snapshot 逐字不动）

### 复用既有 childRows（实施核实：childRows 本就经 currentChildRefs 过滤）
- `TaskState.childRows(limit)` 已是 G1 收敛谓词的有界投影（≤64、result clip 4096）——**不新增方法**；
  仅 additive 补投影字段 `stopDecision`（currentSnapshot 的 acceptance 兜底与 snapshot 同口径）。
- **不改** currentChildRefs/childRows 过滤语义（面板 agents 表/复核/重试沿用既有 childRows 口径）。

### TaskBoardModel.currentSnapshot(session, jobs)
- todos：当前 TodoList 全量（计划顺序；已完成✓保留——用户确认的主流语义）。
- children：`state.childRows(64)`；**running 排前**，其余保持派发序（稳定）。
- background：仅 `!job.status.settled()`（RUNNING/QUEUED/VERIFYING/WAITING_*）；已结束后台=历史，不入条。
- 行序：todos → children(running 先) → 活跃 background。
- `snapshot()`/`render()` 逐字不动：面板 board 段与 /tasks 文本仍全量账本（用户确认面板保留全量）。
- 新引导进来：修订推进 → 旧修订已结束 child 自动出条；agent 经 TodoWrite 追加的新待办 ≤1s 上条
  （轮询+signature 既有机制，不新增事件通道）。

## 3. I2 任务条 UI 美化（TaskStrip + workbench.css + MainWindow 边距）

- 卡片化：圆角 10、四边 subtle 边框、-wb-surface 底；MainWindow 给 taskStrip 设
  `VBox.setMargin(0,10,6,10)` 悬浮卡观感（conversationColumn 其余布局不动）。
- 头部：chevron + 摘要 Label（summaryText 逐字保留，含 H1 徽标）+ **细进度条**
  （ProgressBar prefWidth 84/maxHeight 5，track=-wb-border-subtle、bar=-wb-accent，圆角 3）。
  进度=counts done/total（新静态 `progress(rows)`，空=0）。
- 明细行改结构化 HBox：图标 Label（✓/▶/○ 按态取色：done=-wb-muted、active=-wb-accent-strong、
  pending=-wb-secondary）+ 标题 Label（grow、ellipsis、done 灰显）+ **状态徽标 chip**
  （task=中文状态：运行中/待复核/已完成/已取消/失败中断/中断待复核/已暂停；background=exit=N 或中文状态；
  todo 无 chip）。chip 圆角 4、-wb-elevated 底、10.5px；active chip=-wb-highlight 底+accent-strong 字。
- 行 hover=-wb-hover 圆角 6；行 padding 2 8；rowsBox spacing 3；滚动 maxHeight 160→200。
- "…共 N 项" 改链接色（-wb-link）。
- 新静态（headless 可测）：`chipText(BoardRow)`、`iconClass(BoardRow)`（返回 done/active/pending 后缀）、
  `progress(List<BoardRow>)`。`rowLabel/summaryText/signature/counts/currentTitle/icon/clip` 逐字保留
  （rowLabel 用作行 tooltip，测试特征化不动）。
- MAX_ROWS=8 不变；过滤后行数自然收敛。

## 4. I3 任务面板美化（TaskDashboard，数据全量不动）

- agents 表：状态列 cellFactory → 中文状态 chip Label（样式类 agent-status-running/done/failed/other）；
  表加样式类 agents-table（行 hover/选中取色、表头 -wb-surface）。
- refresh 时 agents 列表 **running 排前**（稳定排序；选中项按 id 恢复的既有逻辑不动）。
- board TextArea 加样式类 board-ledger（12px、-wb-reader 底、内边距）；feedback Label 加
  dashboard-feedback（accent-strong、wrap）。
- 中文状态映射私有静态 zhStatus(String)（与 TaskStrip.chipText 同口径文案，GUI 各自持有不跨层依赖）。
- 其余页签/按钮/交互逐字不动。
