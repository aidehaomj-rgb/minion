## 1. 系统提示词瘦身：领域规则迁为内置技能

### 现状与问题

`SystemPromptBuilder.BUILTIN`（SystemPromptBuilder.java:18-52）约 3000+ 字，其中四段领域工作流
**每轮无条件注入**，与任务无关时也占用上下文并干扰规则注意力：

| 段 | 行 | 内容 |
|---|---|---|
| 本地绘图 | 24 | Artwork/visual-design/Matplotlib/ViewImage 复核规则 |
| 读图 | 25 | Read/ViewImage 真实像素、分区局部、裁剪旋转、不编造型号 |
| 分析/材料 | 26 | PDF inspect/pdf_read/pdf_view、Excel textColumns/merge_audit、docx 大纲/证据/validate |
| OFD + 书生GD | 27-28 | ofd_read/ofd_view/ofd_ocr、gd_read、exportPath、Knowledge import |

主流做法（Claude Code/Codex/ZCode）：核心提示词精简，领域工作流放技能/工具描述，匹配才加载。
本项目已有完整技能路由（BuiltinSkills + Skill 工具按需注入 + SkillResidency 驻留退场），直接复用。

### 方案

1. **本地绘图段** → 并入现有内置技能 `visual-design` 正文（BuiltinSkills.java:11-18）。
   合并去重，保留 VisualDesignSkillTest 全部锚定短语（Artwork/Matplotlib/不自动切换/未视觉核验/真实数据/不是专用图像生成模型）。
2. **读图段** → 新内置技能 `image-reading`，description 写明触发条件
   （"用户给出本地图片路径、需要看清图中文字/细节、核对截图或照片内容时"）。
   **BUILTIN 保留一行核心安全规则**："用户给出本地图片路径时，必须 Read/ViewImage 让真实像素进入上下文，文件名/OCR/列目录不能替代看图"——
   防止弱模型不加载技能就编造图片内容；裁剪/旋转/分区等操作细节移入技能。
3. **分析/材料段** → 新内置技能 `document-materials`（PDF/Excel/DOCX 材料工作流），
   description 覆盖"读 PDF/Excel 数据分析之外的材料撰写、文档提取、报告生成"。
   与现有 `data-analysis` 技能边界：data-analysis 管 pandas 统计分析，document-materials 管文档读取与材料成文。
4. **OFD + 书生GD 两段** → 新内置技能 `ofd-gd-documents`，description 明确"OFD/书生GD 附件读取与预览"。

BUILTIN 其余内容（通用规则 1-10、工具按需加载、多阶段任务、子任务、长对话记忆）**不动**。
技能清单注入机制不变：新技能自动出现在"=== 可用技能 ==="列表，模型按 description 匹配后经 Skill 工具加载。

### 预期收益与风险

- 每轮省约 800-900 token（四段 ~1200 汉字），长会话累积显著；无关任务不再受领域规则干扰。
- 风险：弱模型可能不加载技能就处理 OFD/材料。缓解：description 触发词写全（OFD/GD/PDF/材料/报告等），
  读图保留 BUILTIN 一行兜底；OFD/材料属低频任务，技能路由正是为低频领域设计。
- 不改 SkillResidency/压缩/门禁任何行为。

### 测试

- 新增 `BuiltinSkillsDomainTest`：三个新技能存在、description 含触发词、正文含关键工具名与禁令
  （ofd_view/gd_read/exportPath/textColumns/merge_audit/docx_validate/ViewImage 裁剪等）。
- 新增断言：BUILTIN 不再含 "OFD附件只预览前3页"、"书生GD"、"分析/材料" 段原文；仍含读图兜底一行。

## 2. 重试策略：指数退避 + 抖动 + Retry-After；400 响应体落日志

### 现状与问题

- `RetryPolicy.transientErrors()`（RetryPolicy.java:11-13）固定 5s 间隔、20 分钟墙钟。
  429 限流下固定间隔持续撞限流窗口；多会话并发重试同步形成脉冲。主流客户端一律指数退避+抖动，并尊重 Retry-After。
- 400 偶发根因未定位（2026-11-15 性能文档第三轮遗留）：LlmException 已携带完整 body，
  但 DeepSeekClient 未落盘，事后无法排查。

### 方案

1. **RetryPolicy 增加指数退避能力**（保留旧线性构造器与语义，RetryPolicyTest 自定义实例用例不动）：
   - 新增字段 `multiplier`（double）、`jitterRatio`（double），新构造器重载。
   - `delayMs(attempt)`：multiplier>1 时 = min(maxDelayMs, initialDelayMs × multiplier^(attempt-1))，否则维持线性公式。
   - 新增 `nextDelayMs(attempt)`：在 delayMs 基础上施加 ±jitterRatio 抖动（ThreadLocalRandom，JDK8 内置），结果 ≥0。
   - `transientErrors()` 改默认：initial=5s、multiplier=2、maxDelay=60s、jitter=0.2、maxTotal=20min。
     序列约 5/10/20/40/60/60…（±20%），总预算不变。
   - AgentLoop.java:1608 与 SubAgentLoop.java:269 的 `delayMs` 调用改 `nextDelayMs`。
2. **Retry-After 支持**：
   - LlmException 新增 `retryAfterMs` 字段（long，0=无），新构造器重载，旧构造器委托（默认 0）。
   - DeepSeekClient 两处非 2xx 抛出点（:390/:530）读取 `Retry-After` 头：秒数或 HTTP-date 均解析，
     负值/非法/超过 5 分钟一律忽略（防服务端异常值把重试挂死）；经 `LlmException.of` 新重载传入。
   - 两处重试循环：`delay = max(policy.nextDelayMs(attempts), last.retryAfterMs)`。
3. **400 响应体全文落诊断日志**：
   - DeepSeekClient 非 2xx 抛出前 `DiagnosticLog.warn("llm", "HTTP <code> <url去query> body=<全文>")`。
   - body 上限 64KB 截断（保护 2MB 日志滚动）；经 SecretRedactor 脱敏后写入。
   - 覆盖所有非 2xx（400/413/422/429/5xx），不只 400——同类根因排查一并受益。

### 测试

- RetryPolicyTest：更新 transientErrors 默认参数断言（锚定旧固定 5s 的 3 个用例按新语义改写）；
  新增指数序列、封顶、抖动边界（0.8×base ≤ next ≤ 1.2×base）、multiplier=1 回退线性用例。
- DeepSeekClientTest（mockwebserver）：Retry-After 秒数/HTTP-date/非法值解析；400 时 DiagnosticLog 含全文。
- AgentLoop/SubAgentLoop 重试用例：retryAfterMs 大于策略延迟时取大值。

## 3. Edit 失败返回最近匹配提示

### 现状与问题

EditTool.java:105-107 匹配失败只回"未找到待替换内容，请先 Read"。弱模型常因缩进/空白差异失败，
然后整轮 Read→重试，浪费一次全文件读取与一轮模型调用。主流（Codex apply_patch/Cursor）有空白归一化回退。

### 方案

**不做模糊替换**（写操作必须精确），只在 count==0 的错误信息里附加定位线索：

1. 将 oldString 与文件内容按行拆分，逐行 trim 后做滑动窗口比对（窗口=oldString 行数）。
2. 唯一候选：错误信息追加
   `第 N-M 行存在仅缩进/空白差异的相似内容：<原文首行截断≤120字>。请按文件实际缩进修正 oldString 后重试。`
3. 多个候选：追加 `有 K 处仅空白差异的相似内容（首处第 N 行），请提供更精确的 oldString。`
4. 零候选：维持原错误信息不变。
5. 成本护栏：文件 >20000 行或 oldString >100 行时跳过扫描（直接原错误），避免大文件 O(n×m) 卡顿。
6. 行号按文件原始行（CRLF 归一化不影响行计数）；提示中的原文按文件实际编码解码后的文本。

### 测试

EditToolsTest 新增：缩进差异唯一候选→错误含行号与"相似内容"；多处空白差异候选→含处数；
完全无关内容→错误不含"相似内容"（原语义不变）；既有 edit_noMatch_returnsError 保持通过（仍含"未找到"）。
