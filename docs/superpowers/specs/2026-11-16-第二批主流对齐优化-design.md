## 项 5：Grep/Glob 大仓性能 + .gitignore 尊重

### 现状

- `GrepTool`（188 行）/`GlobTool`（142 行）纯 Java `Files.walkFileTree` 全量遍历；
  Grep 逐文件 `TextFiles.readAllLines` 后逐行正则，大仓（node_modules/target 等）慢且搜进忽略目录。
- 两者均**不读 .gitignore**；Grep 不跳过二进制文件；上限语义已完善
  （Grep 显示 250 条 + 30k 字符、全量落盘；Glob 200 条截断）。

### 方案

**A. 可选 ripgrep 旁路（探测到才用，探测不到行为不变）**

新增 `core/tools/search/RipgrepSidecar.java`：

- 探测顺序：`<jarDir>/rg.exe` → `<jarDir>/tools/rg.exe` → PATH 上的 `rg`；
  启动 `rg --version` 验证可执行，结果缓存（进程级，一次探测）。
- **随包分发（用户确认）**：rg.exe 放入离线包，默认启用提速。
  **Win7 兼容约束：固定 ripgrep 13.0.0**（14.x 起要求 Win10，本项目目标环境含 Win7）。
  仓库存放 `offline-package/ripgrep/rg.exe`（含 LICENSE/校验记录 README）；
  现有打包脚本为按版本 jar-diff 补丁器，rg.exe 复制步骤留待下一轮打包时加入（本批不打包）。
- 提供包级注入口（测试可强制"无 rg"走 Java 回退）。

GrepTool 接入：

- 命令：`rg --no-config --no-require-git --no-ignore-parent --no-ignore-dot --no-ignore-exclude
  --hidden --no-messages --no-heading --with-filename -n --sort path --color never [-i]
  -g '!.git' [-g '!<落盘目录>/'] -e <pattern> .`，
  进程工作目录 = 搜索根（输出相对路径，规避 Windows 盘符冒号解析歧义）。
- `--no-require-git`：无 .git 目录也尊重 .gitignore；`--hidden` 保持"隐藏文件也搜"的旧语义；
  `--no-ignore-parent/dot/exclude` 对齐 Java 版"只读根及以下 .gitignore"；
  实测 `--no-require-git` 下 rg 不再特判 .git，需显式 `-g '!.git'` + Java 侧路径分量双保险。
- **旁路适用性守卫（语义对齐）**：非 ASCII 模式不走 rg（rg 按 UTF-8 搜索，GBK 文件中文会漏配，
  Java 遍历有 GBK 回退兜底）；含 `\b\B\w\W\d\D\s\S` 转义的模式不走 rg
  （Java 默认 ASCII 语义 vs rg Unicode 语义，中文邻接处行为不同）。
  已知可接受边角：`-i` 时 rg 为 Unicode 折叠、Java 为 ASCII 折叠（仅影响 Kelvin 符号等罕见字符）。
- 逐行读 stdout，按 `路径:行号:内容` 解析（正则取首个 `:数字:`），复用现有显示/落盘双上限、
  `truncateLine`（1000 字符）、相对/绝对路径反显与"未匹配/共 N 条"文案——**输出契约不变**。
- 回退条件：rg 不存在、启动失败、正则语法不兼容（Rust regex 不支持 lookahead 等，rg 退出码 2）、
  IO 异常 → 重置显示/计数/落盘状态后走原 Java 遍历。回退对用户透明（诊断日志记一行）。
- `--sort path` 保证输出顺序稳定（牺牲并行换确定性，仍远快于 Java 遍历）。

GlobTool 接入：

- 命令：`rg --files --no-config --no-require-git --no-ignore-parent --no-ignore-dot
  --no-ignore-exclude --hidden --no-messages --sort path -g '!.git' .`——
  rg 只做快速枚举 + gitignore 过滤（rg 的 gitignore 引擎即 git 参考语义），
  **glob 匹配由现有 Java PathMatcher 后置过滤**（工作区相对/根相对/绝对三写法、
  无斜杠模式仅根层、`**/` 零层变体全部原样保留），避免 rg glob 与 Java glob 语义差异。
- 读满 200 条即销毁进程；失败丢弃本根已收集结果回退 Java 遍历；路径反显格式不变。

**B. Java 回退路径同步补强（无 rg 时也受益）**

新增 `core/tools/search/GitignoreFilter.java`（Grep/Glob 共用）：

- 遍历中按目录加载 `.gitignore`（根目录 + 各级子目录，规则就近叠加）；
  支持常见语法：注释 `#`、取反 `!`、目录限定尾 `/`、锚定头 `/`、`*` `?` `**` `[]`
  （转 Java PathMatcher glob）；后匹配规则优先；父目录被忽略则整棵子树跳过。
- 不支持的边角（转义 `\#`、复杂嵌套取反的 git 精确语义）按"宁可多搜不漏搜"处理并注释说明。
- 恒跳过 `.git` 目录（现状连 .git 都搜，属修复）。
- Grep Java 回退增加二进制跳过：读文件前 8KB 含 NUL 字节即跳过（与 rg 默认行为对齐）。

**行为变化声明**：有 .gitignore 的仓库中，被忽略文件不再出现在 Grep/Glob 结果里
（主流对齐的预期变化）；无 .gitignore 的目录行为不变。显式指定被忽略目录为搜索根时仍直搜
（root 自身不被过滤，只过滤其下被忽略内容——与 rg 语义一致）。

### 测试

- GitignoreFilter 单测：注释/取反/目录限定/锚定/**/子目录叠加/恒跳 .git。
- Grep/Glob 回退路径夹具测试：带 .gitignore 的临时目录，忽略文件不出现、根直搜例外、二进制跳过。
- 旁路测试：用仓库 vendored rg.exe（Assume 守卫，缺失则跳过）+ 注入"无 rg"验证回退；
  rg vs Java 输出逐行一致性对照（gitignore 夹具）、环视语法回退、GBK 中文兜底、落盘契约保持。

## 项 6：token 估算按模型校准（平滑 + 持久化 + 图片按尺寸）

### 现状

- `TokenCounter`：中文 0.7/字、其他 0.25/字符；图片固定 500 token/张。
- `ContextManager.observeRequestTokens`（AgentLoop:1660 / SubAgentLoop:332 每请求调用）：
  `inputTokenScale = max(1.0, 服务端总输入/本地总估)` —— **单样本直取**，无平滑、无持久化，
  会话重启即丢；一个异常样本（服务端缓存/计数口径差异）即拉偏后续所有估算。
- `UsageTracker.observeCalibration` 仅观测展示，不参与估算（保持不动）。
- 图片 500 粗估对 Qwen 视觉（≈每 28×28 像素 1 token）大图严重低估，
  靠总量 scale 兜底会把"含图请求"的膨胀比例误带到后续无图请求。

### 方案（三小步，均不触碰 150K/窗口配置）

**A. 非对称平滑（实施前核查修正）**：现有测试固化了"估算必须立即跟上服务端 usage"的
安全语义（usage 突增时立刻触发压缩），对称 EWMA 的向上滞后会导致压缩延迟→超窗风险。
改为**向上立即、向下平滑**：

- 样本比 ≥ 当前 scale：直取样本比（服务端总量是事实，向上不滞后、**不设上限**——
  原设计的 4.0 上限会低估真实用量，作废）；
- 样本比 < 当前 scale：`scale = 0.7*旧值 + 0.3*样本比`（图片滚出窗口后比例回落，
  缓慢衰减而非单样本直落，防抖动）；
- 保留 ≥1.0 下限（宁高估勿低估）。首样本直取。
- `observeInputTokens`（旧接口）同口径。现有校准测试全部语义不变、无需改断言。

**B. 按模型指纹持久化**：新增 `core/context/TokenCalibrationStore.java`，
落盘 `<jarDir>/.session/token-calibration.json`：`{指纹 → {scale, samples, updatedAt}}`。

- 指纹 = provider + url + modelName 的 SHA-256（复用 UsageTracker 指纹思路，不共享状态）。
- ContextManager 增加 `calibrationKey` 注入口（AgentLoop/SubAgentLoop 建会话时从 ModelConfig 传入；
  未注入则退化为纯内存，行为同旧版）。
- 启动/换模型时读入作为先验；每次更新后节流写盘（≥30s 间隔，会话落盘时机顺带 flush）。
- 文件损坏/缺失静默从 1.0 开始（学习态数据，非用户配置，不进备份承诺范围）。

**C. 图片按真实尺寸粗估**：新增 `core/llm/ImageTokens.java`：

- 解码 base64 头部（≤256KB），解析 PNG IHDR / JPEG SOF / GIF / BMP 宽高；
  `tokens = clamp(ceil(w/28)*ceil(h/28), 500, 16384)`；解析失败回退 500。
- 依据：Qwen2.5-VL 系列公开计费口径（28×28 patch ≈ 1 token，默认 max_pixels≈12.8M）；
  下限 500 保持小图旧粗估（保守方向），上限 16384 防超大图炸估算。
- `ImagePart` 增加 transient 缓存字段，`TokenCounter.estimateMessages` 与
  `ContextBudget.estimate` 改用之；Gson 会话存档不受影响（transient）。
- 这是**本地启发式改进**，不是把服务端总量摊成分项——"No invented per-part usage"
  原则与 `describeUsage` 展示口径不变，总量仍由服务端 usage 校准。

### 测试

- EWMA：序列收敛、下限 1.0、上限 4.0、首样本直取、异常样本不 runaway。
- Store：读写 roundtrip、损坏文件容错、节流、指纹隔离（换模型不串）。
- ImageTokens：测试内 ImageIO 生成 PNG/JPEG 验证尺寸解析、下限/上限/坏数据回退 500、缓存生效。
- 回归：现有 ContextManager/TokenCounter/UsageTracker 测试全绿（估算变大的用例按新口径修正断言）。

## 项 7：细粒度审批（命令前缀白名单，降低确认疲劳）

### 现状

- `ConfirmGate.isWhitelisted`：Bash 仅按 `DangerousCommands.firstToken` **单词精确匹配**
  `confirm.whitelist.commands`。白名单 `git` 会放行 `git push --force`——粒度太粗，
  用户要么不敢加白名单（每次确认），要么加了过宽（危险）。
- 现有洞：`git status && rm -rf x` 这类链式命令，首 token 白名单直接放行整条。
- W（APPROVE_WHITELIST）落盘首 token；会话放行/确认跳过/三档权限语义已完善，不动。

### 方案

**A. 前缀规则（复用现有配置键，向后兼容）**

`confirm.whitelist.commands` 条目含空白 → 解释为**前缀规则**：
命令前 N 个 token 逐一归一化（小写、剥引号、basename、去 .exe，复用 firstToken 的归一化逻辑）
后与规则 token 序列相等才命中。例：

- `git status` 放行 `git status --short`、`"C:\Program Files\Git\cmd\git.exe" STATUS`；
- 不放行 `git push`、`git statusx`。
- 单词条目 = 旧语义（首 token 匹配），已有配置不受影响。

**B. 安全护栏（收紧，属安全修复）**

- **链式守卫（仅前缀规则，用户确认）**：命令含 `; & | < > 反引号 $( 换行` 任一元字符时，
  **前缀规则**不命中，回到正常确认；堵 `git status && rm -rf x` 借前缀规则绕过的洞。
  **旧单词条目不收紧**（用户确认）：`npm` 白名单后 `npm a && npm b` 仍按旧语义放行，兼容优先。
- **危险首 token 不禁止（实施前核查修正）**：`BashTool.isHighRisk` 就是
  `DangerousCommands.isDangerous`——**只有危险命令才会走到白名单检查**，
  `git status` 这类安全命令本来就不弹确认。前缀规则的价值恰恰是窄化危险命令
  （`del /q` 比单词 `del` 窄、`taskkill /f /im excel.exe` 只放行杀 Excel）。
  故前缀规则允许危险首 token，安全由"≥2 token + 链式守卫 + 用户手写配置"保障；
  原设计的"危险词护栏"作废（会让前缀规则完全无用）。
- 归一化口径：首 token 复用 firstToken（剥引号/basename/.exe/小写）；
  其余 token 仅剥引号+小写（**不做 basename**，避免 `del /q *.tmp` 意外匹配 `output\*.tmp`）。
  token 级精确前缀相等，不是字符串前缀。
- 前缀规则只作用于 BashTool（SshExec 远端确认本批不动，后续另议）。

**C. W 键语义不变**：仍落盘首 token（可预期、兼容）；前缀规则由用户手改
`config.properties` 添加，README 给示例。不改确认卡片 UI。

### 测试

- 前缀命中/不命中/归一化（引号、大小写、全路径、.exe）；
- 链式守卫（&&、;、|、重定向、反引号、括号、换行；引号内的字面元字符不误伤）；
- 危险命令窄化（`del /q` 命中、`del /s` 不命中）；旧单词条目兼容；W 落盘仍为首 token；
- read-only/full/会话放行/越界读写各链不受影响（现有 ConfirmGate 测试全绿）。

## 项 8：AgentLoop 拆分第一步（完成裁决抽出，A/B 验证）

### 现状与风险

  `docs/2026-11-15-性能与并发优化.md` 已点名暂缓拆分项：
  StreamRecoveryPolicy / StopAdjudicator / CompactionService。

新增 `core/agent/StopAdjudicator.java`，搬移：

- `stopSnapshot`（2400-2512，112 行）
- `pendingExecutionReason`（2519-2554）
- `hasStructuredWork`（2394-2398）
- `internalEvidencePath`（静态，仅 stopSnapshot 使用）

依赖注入（构造器）：`Session`、`ReliabilityService`、`Predicate<Path> evidencePathAllowed`、
`Supplier<ExecutionMode>`；每轮可变字段（childHost / runtimeJobs / runtimeJobProblem）
经小型参数对象 `StopContext` 传入 snapshot 方法，避免持有 AgentLoop 引用。

AgentLoop 保留**同签名私有委托**（ReplyHeuristics 拆分先例）：
`stopSnapshot(...)` 一行转调 adjudicator，runTurn 三处调用点（1888/2027/2099）零改动。

（hasPendingTodos 经 StopContext 谓词传入）。

静态文本助手（looksLikeInterruptedReply / hasTaskCompleteMarker / completionTimeLine /
buildNoActionRecoveryHint / buildMalformedToolRecoveryHint / hasVisibleText / repeatedControlAction）
本批**不动**——已有测试经 AgentLoop 静态入口引用，且多为纯函数，搬移收益低、churn 高。

### A/B 验证

1. 搬移**前**：新增特征化测试（characterization），用夹具 Session 驱动
   `stopSnapshot` 委托入口，固化 facts/receipts/blocking/proof 的 JSON 快照断言
   （覆盖：无任务、有断点未核验、子任务未核对、验收规则未过、不可读步骤、交付证明成立等分支）。
2. 搬移**后**：同一组测试必须逐字节通过；AgentLoopTest 95 项 + UnifiedStopLoopTest +
   CompletionHeuristicBoundaryTest + LegacyStopFixtures 全绿；全量回归。
3. 预期效果：AgentLoop 减 ≈200 行，完成裁决可独立单测（不再必须构造整个 AgentLoop）。

### 明确不做

- runTurn 分阶段状态机（codex-rs 路线）——后续批次，需单独设计。
- StreamRecoveryPolicy / CompactionService 抽出——同上。
- 任何门禁判定条件、文案、放行顺序的"顺手优化"。
